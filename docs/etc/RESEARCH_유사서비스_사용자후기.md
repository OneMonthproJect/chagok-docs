### 1.4 기능이 겹친다는 사실을 인정한 범위 결정

- **예약·이력·주기 알림**은 기존 제품에도 있다. 차곡의 새로운 발명이나 유일한 기능이라고 표현하지 않는다.
- **고객 앱 미제공**은 차주용 앱과 사용 접점이 다르다는 뜻일 뿐, 정비소용 소프트웨어 전체에 대한 독자적 차별점이 아니다.
- **정비소별 데이터 격리**는 제품 간 비교 우위가 아니라 반드시 지킬 접근 통제 원칙이다. 경쟁 제품의 격리 정책은 공개 자료로 비교하지 않았다.
- **직접 연락**은 트레이드오프다. 사장이 대상·문구·시점을 통제하지만 발송과 결과 기록의 수작업은 남는다.
- '미확인'을 '없음'으로 취급하지 않는다(20개 조사 문서 4절의 표기 원칙과 같음).

## 2. 공개 사용자 후기 요지 8건 (원문 재확인 전)

### 2.1 근거 취급 기준

- **우선순위**: 정비소 사장·운영자 → 서비스 어드바이저·정비사·매니저 → 역할이 표기된 관련 실무자 → 차주 후기(간접 지표). 작성자의 직업·업체 규모는 플랫폼의 **자가 표기**로만 알 수 있다.
- **분리**: `후기에 적힌 경험(관찰 자료)` / `차곡의 해석(가설)` / `실제 정비소에 확인할 질문`을 섞지 않는다. 한 사람의 평가를 제품 전반의 사실로 일반화하지 않는다.
- **균형**: 같은 제품에서 도움이 됐다는 경험과 비용·학습·오류·수작업 부담을 함께 적는다. 작성 시점·제품 버전·요금제·리뷰 인센티브가 내용에 영향을 줄 수 있다.
- **자료 한계**: 해외 리뷰 플랫폼의 영어 후기 위주다. 국내 1~5인 정비소의 업무 조건, 문자 앱 사용, 국내 서비스 이용 경험을 대표하지 않는다. 통계적 표본 조사나 제품 순위가 아니다.

### 2.4 읽는 방법

- R-01·R-03·R-04는 운영 역할 표기가 상대적으로 명확하다. R-02·R-06·R-07·R-08은 작성자 유형이 불확실해 관찰 가설의 보조로만 쓴다. R-05는 v15 원문에서 분류하지 않았고, 이번 정리에서 CTO 표기를 정비소 현장 운영 역할로 보기 어려워 보조로 분류했다(이 문서에서 추가한 판단).
- 같은 서비스의 후기가 서로 반대일 수 있다. 그 자체가 "현장 환경에 따라 효과가 달라지는가?"라는 인터뷰 질문이다.
- 별점이나 후기 수가 많다고 정비소 안에서 기록 입력이 빠르다는 뜻은 아니다. 공급사의 성공 사례·마케팅 문구는 독립 후기로 섞지 않는다.

## 3. 후기에서 도출한 업무 질문

| 업무 장면 | 후기에 나타난 상반된 경험 | 차곡의 기존 기능·정책에 연결되는 질문 | 측정·관찰 (신규 기능 요구 아님) |
|---|---|---|---|
| 예약·고객 조회 | 통합 조회가 편리함 ↔ 기본 기능을 찾느라 화면을 많이 옮김 (R-01·R-02·R-07) | 오늘 예약에서 그 고객·차량의 최근 이력을 얼마나 빨리 확인하는가? | 클릭·화면 전환 수, 소요 시간, 잘못 고른 차량 건수 |

| 재점검 대상·연락 준비 | 디지털 연락이 빠름 ↔ 설명·수동 확인은 계속 필요 (R-05·R-08) | 사장이 대상의 근거를 확인하고 문자 초안을 준비하는 데 얼마나 걸리는가? | 대상 확인 → 문자 복사 시간, 대상 오선정, 수작업 단계 |
| 직원 학습·운영 | 기능 통합은 배우기 쉬움 ↔ 기능이 많으면 처음 쓰는 직원에게 부담 (R-02·R-07) | 처음 쓰는 정비사가 도움 없이 핵심 시나리오를 끝내는가? | 첫 시도 완료율, 도움 요청 횟수, 막힌 화면 |
| 도입 부담 | 체계화는 유용함 ↔ 가격·연동·전환 작업이 부담 (R-06·R-07·R-08) | 초기 이력 입력과 기록 누락 부담은 어느 정도인가? | 초기 데이터 확보 방식, 일주일 안의 기록 누락, 도입 의사와 이유 |

이 후기들은 **"모든 소규모 정비소가 수기로 관리한다"를 입증하지 않는다.** 특정 작업의 시간·노력·실수 가능성을 조사할 이유를 줄 뿐이다. 차곡은 경쟁사보다 빠르다고 말하기 전에 자기 시나리오를 실제 사용자로 측정해야 한다.

**국내 1~5인 정비소 운영자를 직접 인터뷰하거나 업무를 관찰한 적은 아직 없다(미실시).**

### 4.1 정비소 실무자 인터뷰·업무 관찰안 (미실시)

대상은 1~5인 독립 정비소 사장·직원이며, 가능하면 전산 사용 여부가 다른 곳을 함께 본다. 모집 수·섭외 방식·동의 절차·일정은 실제 조사 전에 정한다. 실시 전에는 응답 비율이나 소요 시간을 추정하지 않는다.

1. 전화나 현장 예약이 들어오면 고객·차량을 **어디서 먼저 찾고**, 어떤 정보를 다시 입력하는가?
2. 오늘 들어올 차량의 **이전 정비 이력**을 찾으려고 무엇을 확인하며, 얼마나 걸리는가?
3. 방문 뒤 **주행거리·정비 항목·메모**는 언제, 누가, 어디에 입력하는가? 나중에 몰아서 쓰는가?
4. 이력이 없거나 다른 정비소에서 수리했다는 고객은 어떻게 기록하는가?
5. 다음 점검 시기가 된 고객을 실제로 찾아 연락하는가? 한다면 **대상 선정 → 내용 준비 → 연락** 중 어디에 시간이 가장 드는가?
6. 문자 초안이 있어도 **직접 전송·연락 결과 기록**이 번거로운가? 자동 발송을 원한다면 이유는?
7. 신규 직원이 예약 확인·방문 기록을 익힐 때 어느 단계에서 도움을 요청하는가?
8. 새 프로그램을 쓴다면 기존 기록 옮기기·가격·기기·접속·개인정보·교육 중 무엇이 망설여지는가?

**관찰 기록 틀**: `정비소 구분 코드 / 직무 / 직원 수 / 현재 기록 도구 / 상황 / 실제 단계 / 시작·종료 시각 / 재입력·오류·문의 / 발언 요약 / 조사자가 해석한 가설 / 차곡 검증 대상 / 동의 여부`. 개인정보·실제 차량번호·연락처는 기록하지 않고, 참여자의 허락 없이 발언을 실명으로 인용하지 않는다.

## 5. 기획 반영 여부와 범위 보호

- **반영한다(문서·검증)**: 운영자가 어떤 업무에 얼마나 시간을 쓰는가라는 문제 정의의 관찰 근거, 업무 동선별 사용성 시험, 첫 사용 난도, 직접 연락의 수작업 부담에 대한 확인 질문.
- **지금은 반영하지 않는다(기능·정책)**: 자동 문자 발송, 견적·POS·청구·결제·재고, 태블릿 전용 앱, 통합 마케팅, 새 DB 필드·API·화면. 후기 하나로 P0·P1·P2·Non-goal을 바꾸지 않는다.
- **기능을 바꾸자는 의견이 나와도** 팀의 `결정` 이슈·범위 판정(`chagok-scope-guard`)·13 changelog 없이 확정 정책으로 넣지 않는다.
- **발표 문구**: "공개 사용 후기에서는 업무 통합의 편리함과 함께 입력·탐색·학습·연락 방식의 부담이 언급된다. 차곡은 이 가운데 **예약 → 이력 → 기록 → 재점검 → 연락 준비 → 재예약** 경로에서 실제 작업 시간과 단계 수를 확인하려 한다." (후기 원문 재확인 전에는 "공개 후기 요지 기록" 수준으로 말한다.)
