# 03 공통 클론·개발환경

> 기준: 2026-11-24, 각 레포 develop의 README·`.env.example`·`build.gradle`·`package.json`·`vite.config.js`·CI 파일과 대조. 이 문서는 요약이고 **원본은 각 레포 README**다. 비밀값은 적지 않는다.
> 이 문서의 명령은 작성자가 새 PC에서 처음부터 실행해 본 것이 아니다(**NOT VERIFIED** — 첫 팀원이 확인 후 결과를 #77 또는 후속 이슈에 남긴다).

## 1. 준비물

| 도구 | 버전 (근거) |
|---|---|
| Git + Git Bash | 최신 (스크립트는 Git Bash 기준) |
| JDK | **21** (`build.gradle` toolchain, backend-ci) |
| Gradle | 설치 불필요 — Wrapper |
| Node.js / npm | **22 LTS** (frontend README, frontend-ci `node-version: "22"`) |
| MySQL | **8** (backend-ci `mysql:8.0`) |
| GitHub CLI `gh` | 선택 (이슈·PR 조회) |
| Claude Code | 선택 (코드 레포 루트에서 실행) |

GitHub 조직 `OneMonthproJect` 세 레포 접근 권한이 있어야 한다(팀원 계정별 권한은 이 문서에서 확인하지 못함 — 형상관리자에게 확인).

## 2. 처음 한 번: 클론

**Git Bash**
```bash
mkdir chagok && cd chagok
git clone https://github.com/OneMonthproJect/chagok-docs.git
bash chagok-docs/scripts/setup-workspace.sh OneMonthproJect   # backend·frontend clone, 세 레포 develop 전환, .claude 복사
for r in chagok-docs chagok-backend chagok-frontend; do git -C "$r" status -sb; done
```

**PowerShell** (스크립트는 bash라 Git Bash로 부른다)
```powershell
mkdir chagok; cd chagok
git clone https://github.com/OneMonthproJect/chagok-docs.git
& "C:\Program Files\Git\bin\bash.exe" chagok-docs/scripts/setup-workspace.sh OneMonthproJect
foreach ($r in 'chagok-docs','chagok-backend','chagok-frontend') { git -C $r status -sb }
```

- 기본 브랜치는 `main`, 작업 기준은 **`develop`**. `main`에서 기능 브랜치를 만들지 않는다.

## 3. 작업할 때마다

```bash
git switch develop
git pull --ff-only origin develop
git switch -c feature/#<그 레포 이슈번호>-<영문-소문자-이름>    # 예: feature/#17-cycle-calc
```
브랜치 종류: `feature/`·`fix/`·`docs/`·`chore/` (CONTRIBUTING 2장). 번호는 **그 레포의** 이슈 번호.

## 4. 백엔드 (`chagok-backend`)

### 4.1 DB 준비 (README 「로컬 DB 준비」)

용도별로 DB를 나눈다. 같은 DB를 두 용도로 쓰지 않는다.

| 용도 | DB 예 | 내용 |
|---|---|---|
| 개발 `bootRun` | `chagok` | Flyway가 만든 표 + 내가 넣은 데이터 |
| 테스트 `dbTest` | `chagok_test` | **비어 있어야 함** |
| 시연 | `chagok_demo` | 시연 시드만 (`db/seed/run-demo-seed.sh`, DB관리 승인) |

**내 PC의 MySQL**에 만든다. 팀 공용 DB에 DDL을 직접 실행하지 않는다. 표는 만들지 않는다(Flyway가 V1부터 적용).

### 4.2 환경변수 (`.env`, Git 제외)

| 키 | 값 |
|---|---|
| `DB_URL` | 예: `jdbc:mysql://localhost:3306/chagok?characterEncoding=UTF-8&serverTimezone=Asia/Seoul` |
| `DB_USERNAME`·`DB_PASSWORD` | 내가 만든 계정 |
| `JWT_SECRET` | 각자 생성, 32바이트 이상. Git Bash `openssl rand -base64 48`. **공유·커밋 금지**. 비면 서버가 뜨지 않음 |

### 4.3 실행·테스트

| 할 일 | Git Bash | PowerShell |
|---|---|---|
| `.env` 만들기 | `cp .env.example .env` | `copy .env.example .env` |
| 빌드 + DB 없는 테스트 | `./gradlew build` | `.\gradlew.bat build` |
| 서버 실행 (8080) | `./gradlew bootRun` | `.\gradlew.bat bootRun` |
| 상태 확인 | `curl http://localhost:8080/actuator/health` → `{"status":"UP"}` | `curl.exe http://localhost:8080/actuator/health` |
| DB 테스트 (빈 테스트 DB) | `DB_URL='jdbc:mysql://localhost:3306/chagok_test?characterEncoding=UTF-8&serverTimezone=Asia/Seoul' ./gradlew dbTest` | `$env:DB_URL='jdbc:mysql://localhost:3306/chagok_test?characterEncoding=UTF-8&serverTimezone=Asia/Seoul'; .\gradlew.bat dbTest; Remove-Item Env:DB_URL` |
| 다시 돌리기 | `./gradlew dbTest --rerun` | `.\gradlew.bat dbTest --rerun` |

- 리포트: `build/reports/tests/test/index.html`, `build/reports/tests/dbTest/index.html`. **SKIPPED는 통과가 아니다.**
- 머지된 `V1__init.sql`을 고치지 않는다. `flyway repair`·`flyway_schema_history` 직접 수정으로 checksum 오류를 숨기지 않는다 → DB관리와 원인 확인.

## 5. 프론트엔드 (`chagok-frontend`)

| 할 일 | Git Bash | PowerShell |
|---|---|---|
| 환경 파일 | `cp .env.example .env.local` | `copy .env.example .env.local` |
| 설치 | `npm ci` | `npm ci` |
| 개발 서버 | `npm run dev` → http://localhost:5173 | 같음 |
| 검사 (CI와 같은 순서) | `npm run lint && npm test && npm run build` | `npm run lint; npm test; npm run build` |

| 키 | 값 |
|---|---|
| `VITE_API_BASE_URL` | **비워 둠** → 같은 주소 `/api`로 요청 |
| `VITE_DEV_PROXY_TARGET` | `http://localhost:8080` — 개발 서버가 `/api`·`/actuator`를 백엔드로 넘김 (CORS 없이) |
| `VITE_USE_MOCK` | 백엔드 없이 화면을 만들 때만 `true`, **`.env.development.local`에** (운영 빌드에서는 무시) |

`VITE_` 값은 브라우저에 그대로 들어가므로 비밀값을 넣지 않는다.

## 6. FE ↔ BE 연결 확인

1. 백엔드 `bootRun` → health `UP`
2. 프론트 `npm run dev` → `http://localhost:5173/login`에 "백엔드 상태: UP"
3. 지금 `/login`은 **임시 상태 확인 화면(`ServerCheck`)**이다. 실제 S-01 로그인은 아직 없다(12 4장 3번).

## 7. Claude 공용 설정

- 원본은 `chagok-docs/.claude/{rules,skills,agents}`. 코드 레포에는 복사본(커밋 안 됨)을 둔다.
- 갱신: `cd chagok-docs && git switch develop && git pull --ff-only origin develop` → 코드 레포 루트에서 `bash ../chagok-docs/scripts/sync-claude.sh`
- 코드 레포의 `.claude/.synced-from`에 복사 원본 SHA·브랜치가 적힌다. docs가 develop이 아니면 경고가 나온다.
- 자세한 것은 [04](04_Claude_스킬_에이전트_사용안내.md).

## 8. 문제 해결

| 증상 | 확인 |
|---|---|
| 서버가 안 뜸 | JDK 21, MySQL 실행, `DB_URL`·계정 권한, `JWT_SECRET`(비었거나 32바이트 미만) |
| Flyway checksum 오류 | 머지된 마이그레이션이 바뀐 것. 고치지 말고 DB관리에게 |
| `dbTest`가 `shop`이 비어 있지 않다고 실패 | 개발·시연 DB로 돌린 것. 빈 테스트 DB를 새로 만든다 |
| 프론트에서 연결 실패 | 백엔드 8080, `VITE_DEV_PROXY_TARGET`, `VITE_API_BASE_URL`이 비었는지 |
| `/login`이 상태 화면만 보임 | 정상 (S-01 미구현) |
| `.claude/`가 비어 있음 | `bash ../chagok-docs/scripts/sync-claude.sh` |
