## 2. 배정 원칙

- 주 담당 1명 + 협업·검증 1명. BE 이슈 = 도메인 패키지(또는 screen) 하나, FE 이슈 = 화면 하나(12 1장, CONVENTIONS).
- **주요 업무는 한쪽(BE 또는 FE)**이다. 4명은 한쪽 개발만 맡고 반대쪽은 계약 확인(협업·검증)으로만 만난다. 예외로 김동윤은 BE가 주 업무이고 FE 2개(6-1·16)를 맡는다(PM 결정, P0-핵심 FE 쏠림 보완).
- 쓰기 도메인(customer·maintenance·reservation·account)은 한 사람에게 몰리지 않게 나누고, 읽기·집계 이슈(visit·target·home·booking)와 순수 계산(cycle)은 운영 업무가 무거운 사람에게 둔다.
- 기능 ID·API 번호·화면 ID·선행은 **12 4장 기준**이다. 분할·추가한 이슈는 12의 부모 번호에 하위 번호를 붙이고 [02](02_P0_개발이슈_생성계획.md)에 근거를 적었다. 이 문서는 사람만 추천한다.
- FE는 08 JSON 예시로 Mock을 만들어 BE보다 먼저 시작할 수 있다(CONVENTIONS 7장 「Mock」).
- DB관리 2명의 DB 권한(마이그레이션·시드 승인)은 공동이다. 기능 개발 배정과 섞지 않는다.
