## 1. 판단

도메인전문가가 기능별 **추천 담당**을 미리 준비하는 것은 적절하다(기능·명세·시나리오를 가장 넓게 보는 역할). 다만 **확정은 하지 않는다**: 업무량·일정은 PM, 이슈 생성·Assignee 지정은 형상관리, DB 영향은 DB관리가 확인한다.

```
→ ③ 이영주·이재성 DB: DB 영향·권한 확인 (P0-핵심은 V1 표만 사용, 새 마이그레이션 없음이 기본)

→ ⑤ 각 팀원: 자기 이슈 확인 → 착수 (PERSONAL 가이드)
→ ⑥ 확정된 영역별 담당을 12 7장에 넣는 docs PR (PM)
```

## 4. 단계별 검토 항목

1. **기능 목록**: 00 P0-핵심 ↔ 04 F-ID ↔ 12 4장 1~17. M2 시나리오 A·B가 1~17로 끝까지 도는지(02 3장 Q8 범위 질문 포함).
2. **추천 배정**: 역할·의존성·운영 부하. DB관리 역할과 기능 개발 배정을 섞지 않는다.
3. **명세 검토**: 06 권한, 07 데이터, 08 API, 09 화면, 10 추적표. D-19 반응형·패널 세부는 해당 FE 착수 전.
4. **전달**: PM에게 업무량 검토, 형상관리에게 이슈 초안. **대신 Assignee를 지정하지 않는다.**
5. **PR 리뷰 참여**: `chagok-spec-sync`·`chagok-contract-checker`로 08 대조. 403·404 격리·409·실패 시 입력 보존·시나리오 A·B.
6. **변경 통제**: 새 기능 의견은 `결정` 이슈 + 전원 합의 먼저(`chagok-scope-guard`). P1·P2로 조용히 넓히지 않는다.
7. **완료 판정**: 작성자 CI와 별개로 다른 사람의 실행 근거. M2 판정은 형상관리, 시연은 전원.

## 5. 의견이 엇갈릴 때

- 역할은 D-14가 원본이다. 영역별 담당은 팀 합의 후 12 7장 docs PR로 기록한다.
- 일정(D-15)은 PM이 정한다. 이 패키지는 날짜를 만들지 않는다.
- 기준 문서끼리 다른 곳(02 3장 Q1~Q13)은 문서를 임의로 고르지 않고 `결정` 이슈 또는 docs 이슈로 올린다(source-of-truth).
- P0-핵심 밖 기능을 이슈에 묶지 않는다.
