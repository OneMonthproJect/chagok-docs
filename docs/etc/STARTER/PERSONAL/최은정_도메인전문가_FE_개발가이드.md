## 4. 첫 개발 순서

1. **도메인 업무 먼저**: 02 3장 Q1~Q13을 PM과 정리(특히 Q2 F-CUS-03 → 6-1 추가, Q13 공통 머리·메뉴 → 3-1 추가, Q8 시나리오 B 범위 → `결정` 이슈 여부). D-19 화면 세부 상태 확인(C05).
2. `develop` 최신화, `npm ci`, lint·test·build 통과.
3. 3-2(공통 UI 5종)를 먼저 — `Modal`·`FormField`·`EmptyState`·`ErrorNotice`·`ItemStatusList`(껍데기·variant), 파일은 [08](../08_구현_파일_소유_충돌방지.md) 5장. 이어서 5번 이슈 열기 → 04 F-CUS-01·02, 08 05·06, 09 S-05·M-01.
4. `feature/#<번호>-customer-list`.
5. `features/customer/`: `types.ts`(08 그대로), `api.ts`, `mocks/`(07 7장 시드 값으로 직접 만든다. feature 사이 공유 fixture 파일은 없다, 실제 개인정보 금지). **customer feature의 첫 이슈이므로 08의 05~09 `types.ts`·`api.ts`·`mocks/`를 전부 만든다**([08](../08_구현_파일_소유_충돌방지.md)).
6. `pages/S05` + M-01. 안내 수신 동의 **기본 미체크**(D-11), 같은 연락처·차량번호가 있으면 먼저 보여 줌, 차종 필수, 저장 중 비활성.
7. 400 `fieldErrors`를 칸 아래에, 네트워크 실패 때 입력 보존.
8. 이영주 4-1 머지 후 실제 연결(2·3 머지로 로그인 가능해진 뒤) → PR. 5번 화면이 생기면 공통 메뉴(3-1)에 "고객·차량" 항목을 한 줄 등록한다.
9. 6 → 9 → 10 순. 6이 머지되면 김동윤에게 알려 6-1(차량 추가)이 `pages/S06`에 붙게 한다. 10번 미리보기는 입력 후 0.5초💡에 API 10 호출, "기록되지 않음" 표시.
