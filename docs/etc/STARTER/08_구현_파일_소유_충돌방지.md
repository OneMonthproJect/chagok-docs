# 08 구현 파일 소유·충돌 방지 (추천안)

> 기준 시각: 2026-11-24, backend `origin/develop` `f562a7b`, frontend `origin/develop` `bf2ab08`, docs develop `cf9ef3f`. **추천안**이다. 이슈 분할·담당은 [01](01_P0_핵심기능_담당배정.md)·[02](02_P0_개발이슈_생성계획.md), 화면 구조는 [07](07_프론트_화면구조_라우팅_컴포넌트_설계.md). 폴더 구조의 원본은 CONVENTIONS 2·7장이고, 이 문서는 **어느 이슈가 어느 파일을 만들고 고치는지**를 정한다.
> 파일 **이름은 추천**이다(CONVENTIONS의 이름 규칙 `…Controller`·`…Service`·`…Repository`·`dto` record를 따름). 이슈를 구현할 때 이름을 바꿔도 되지만 **어느 이슈의 파일인지(경계)는 바꾸지 않는다**. 바꾸면 이 표도 같은 PR에서 고친다.
> 경로 생략: 백엔드는 `src/main/java/com/wanted/chagok/`, 테스트는 `src/test/java/com/wanted/chagok/`, 프론트는 `src/`.

## 1. 결론 (이슈를 더 쪼개야 하나, 충돌은 없나)

- **충돌이 0은 아니다.** 같은 파일을 두 이슈가 고치는 곳이 있다. 다만 아래 규칙으로 **서로 다른 사람이 같은 파일을 동시에 고치는 경우를 없애는 것**이 목표다(같은 사람이 순서대로 고치는 것은 허용).
- **같은 파일을 만지는 이슈는 쪼갤수록 조각 수만큼 겹친다.** 그래서 처음에는 분할 대신 순서로 직렬화하고 3-2(공통 UI)만 더했다. 이후 PM의 일정 목표(시작 후 10~12일) 때문에 큰 이슈를 **새 파일 중심으로** 더 나눴다(backend #42~#45, frontend #35~#37). 겹치는 파일은 **머지 순서와 매일 rebase**로 푼다(아래 6번).
- **백엔드는 공유 파일 충돌이 적다.** `SecurityConfig`는 `/api/**`를 역할로 한꺼번에 열어 두었고(2번만 로그인 `permitAll`을 더함), `ErrorCode`에는 P0-핵심 11개가 이미 있으며, P0-핵심에는 새 Flyway 마이그레이션이 없다.
- **프론트는 충돌 지점이 많다.** `App.jsx` 라우트, `paths.js`, 메뉴, 각 feature의 `types.ts`·`api.ts`·`mocks/index.ts`, `pages/S02/HomePage.jsx`. 3장 규칙으로 줄인다.
- **문서끼리 어긋난 곳 하나(❓ Q14, 6장)**가 이 표의 4-2 한 줄에 걸려 있다.

## 3. 규칙 (요약)

**백엔드**
1. 한 도메인(패키지)은 **한 사람**이 소유한다(customer·item·maintenance = 이영주, reservation·screen/target·screen/booking = 김예린, cycle·account·shop·screen/visit = 김동윤).
2. 도메인의 첫 PR은 `api/`만(계약 PR). 쓰는 쪽은 그 계약이 develop에 들어온 뒤 구현한다.
3. 같은 도메인의 두 이슈는 컨트롤러·dto를 새 파일로 나누고, service·entity·repository는 순서대로만 고친다.
4. 다른 사람 도메인의 `service`·`entity`·`repository`·`controller`를 고치지 않는다. 필요하면 그 도메인 `api`에 메서드를 **더해 달라고** 요청한다.
5. 공유 파일(`SecurityConfig`·`ErrorCode`·`GlobalExceptionHandler`)은 L3.
6. **P0-나머지의 reservation 이슈(#33·#35~#38·#40)는 모두 reservation 주인(김예린) 한 사람이 맡는다**(1번 규칙). 같은 `Reservation` entity·`ReservationService`를 고치는 사람이 하나이므로 사람 사이 충돌이 없고, 한 사람이 **#33 → #36 → #35 → #37 → #38** 순서로 머지하며 앞 PR 머지 뒤 rebase한다. frontend `ReservationPanel`·S-02 관련은 모두 이재성(#31 → #33 → #37 순서로 머지). `account.api`에 메서드를 더하는 #44는 account 주인(김동윤)이 하고 먼저 머지한다. `global/ErrorCode`는 #45가 P0-나머지 코드를 한 번에 추가하므로 각 이슈는 이 파일을 고치지 않는다.

**프론트**
1. 한 `pages/Sxx`는 한 사람이 소유한다(S06만 6과 6-1이 순서대로).
2. `pages/Sxx/route.jsx`가 `{ path, element, menu? }`를 내보내고, `app/routes.js`가 `import.meta.glob`으로 모은다. `App.jsx`는 3-1 이후 화면 이슈가 고치지 않는다.
3. feature별 `types.ts`·`api.ts`·`mocks/`는 첫 이슈가 P0-핵심 전체분을 만든다.
4. feature끼리 import하지 않는다(CONVENTIONS 7장). 조합은 `pages`에서.
5. `shared/ui`는 3-1·3-2만 추가한다.
6. 컴포넌트마다 `*.css`, barrel 없음, `package.json` 변경 금지.
