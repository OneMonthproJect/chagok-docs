## 1. 표현 원칙

| ID | 정책 |
|---|---|

## 3. 정비소 격리

| ID | 정책 |
|---|---|
| POL-20 | 모든 고객·차량·이력·예약 데이터는 정비소 단위로 나뉜다. 로그인한 정비소의 데이터만 보인다 |
| POL-21 | 다른 정비소 데이터를 요청하면 "없음"(404)으로 답한다. 403은 그 데이터가 있다는 사실을 드러내기 때문이다 (D-12) |
| POL-22 | 서비스 관리자는 정비소를 열고 닫을 수 있지만 정비소 안을 볼 수 없다. 서비스 관리자 토큰으로 정비소 API를 부르면 403 |
| POL-23 | 같은 차량(같은 차량번호)이 다른 정비소에 있어도 서로 보이지 않는다. 정비소 간 공동 이력은 없다(Non-goal) |
| POL-24 | 이 경계는 서비스 기능(화면·API) 수준이다. 서버·DB 직접 접근은 운영 정책 영역으로 MVP 밖 |
| POL-25 | 정비소 데이터끼리의 연결(차량→고객, 기록·예약→차량, 기록·예약 목적→정비 항목, 예약 목적→예약, 예약·기록→담당 정비사)은 같은 정비소 안에서만 만든다. 서버가 저장 전에 부모를 그 정비소에서 찾아 확인하고(경로·`vehicleId`는 404, 본문의 정비 항목 id와 담당 정비사 id는 400), DB 복합 FK가 마지막으로 막는다. DB에서 막혔다면 서버 검증 누락이므로 500으로 처리하고 고친다 (M1 결정 A, 07 5.1) |

## 10. 공통 오류 처리 (P0-핵심부터, D-45)

| ID | 상황 | 서버 | 화면 |
|---|---|---|---|
| POL-120 | 저장 중 | — | 저장 버튼 비활성 + 진행 표시. 두 번 눌러도 요청은 한 번 |
| POL-121 | 입력 오류 | 400 `INVALID_INPUT` + 필드별 이유 | 필드 옆에 메시지, 입력값 유지 |
| POL-122 | 저장 실패 | 요청 하나는 한 트랜잭션. 실패하면 그 요청의 변경을 모두 되돌린다 | 입력값 유지, 오류 안내 |
| POL-123 | 중복 예약 | 409 `RESERVATION_ACTIVE_EXISTS` + 기존 예약 번호 | 기존 예약 확인·변경 안내 (POL-103) |

| POL-124 | 동시 수정 | 409 `CONCURRENT_MODIFICATION` (덮어쓰지 않음). 대상: 예약 변경·상태 변경(P0-핵심, POL-102·104), 고객·차량 수정(P0-나머지, `customer`·`vehicle`의 `version`은 V2), 방문 접수·정정·정비 기록 수정(P0-나머지) | 최신 내용을 다시 불러와 보여주고 다시 수정하게 함 |
| POL-125 | 네트워크 오류·응답 없음 | — | 입력값 유지. 저장됐는지 목록·이력에서 확인한 뒤 사람이 다시 저장. **자동 재전송 금지** |
| POL-126 | 인증 만료 | 401 `AUTH_REQUIRED` | 로그인 안내 → 로그인 화면 |
| POL-127 | 권한 없음 | 403 `FORBIDDEN` | 권한 안내 |
| POL-128 | 접근할 수 없는 데이터 | 404 `NOT_FOUND` (남의 것과 없는 것을 구분하지 않음) | "찾을 수 없습니다" |
| POL-129 | 서버 오류 | 500 `INTERNAL_ERROR` (내부 정보·스택은 응답에 넣지 않음) | 공통 오류 안내, 입력값 유지 |

- 오류 코드와 응답 모양은 08 0.2·0.3 하나뿐이다. 화면은 `shared/api/client.ts` 한 곳에서 이 표대로 처리한다.
- 오류를 숨기려고 예외를 모두 잡아 성공처럼 응답하지 않는다.
- 권한·격리는 서버가 판단한다. 화면에서 메뉴를 숨기는 것은 편의일 뿐이다.
- 빈 상태·조회 실패: 화면별 문구·버튼은 09 5장. 조회 실패는 "불러오지 못했습니다" + "다시 불러오기"(수동). 저장 실패는 입력값 유지 + 상단 오류 안내 + 수동 "다시 시도". 자동 재시도·임시 저장은 범위 밖이다.

## 11. 입력 검증 요약 (서버 기준)

| 대상 | 규칙 |
|---|---|
| 고객명 | 1~50자 |
