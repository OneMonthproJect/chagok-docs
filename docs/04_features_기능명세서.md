상태: 작성됨 (2026-11-22 · 최은정(eunjung01230)), 2026-11-23 D-51~D-59 반영 — M1 설계 확정 때 확정

## 0. 표기

- 기능 ID: `F-영역-번호`. 영역: AUTH 인증, HOME 홈, CUS 고객·차량, MNT 정비 기록, VIS 방문 중 안내, CYC 주기 계산, TGT 재점검 대상, RSV 예약, CON 연락, NTF 알림, ADM 서비스 관리자, STF 정비사 계정, ITEM 항목 기준표, STAT 집계
- 역할: 사장(OWNER) · 정비사(MECHANIC) · 서비스 관리자(ADMIN). 사장은 정비사가 할 수 있는 모든 일을 하고 설정·계정·삭제·파기를 더 한다(D-57, 06). 정비 기록 수정·예약 정정은 정비사는 본인 담당 + 3일 이내, 사장은 제한 없음
- 테스트 ID: T-xx 주기 계산(백엔드 `test/.../cycle`), R-xx 예약 규칙, H-xx 정비 기록 수정, K-xx 보관·비활성화, X-xx 정비소 격리(08)
- 상태 용어: 점검 주기 상태 = 미확인/여유/임박/도래. 예약 상태 = 예약/진행중(P0-나머지)/방문 완료/취소/노쇼
- 예약 용어(D-52·D-53): **유효 예약** = 상태 "예약"이면서 예약 날짜 ≥ 오늘, 또는 상태 "진행중"(기존 "진행 중 예약"을 이 이름으로 바꿈). **처리 필요** = 시각이 지났는데 상태가 "예약"인 것(저장하지 않는 표시). **지난 예약** = 예약 날짜 < 오늘(날짜 기준)
- 담당 정비사: 예약·정비 기록을 맡은 사람. 사장·정비사 모두 될 수 있다(D-51·D-57)

## 2. 인증

### F-AUTH-01 사장·정비사 로그인·로그아웃 (P0-핵심)

- **입력**: 아이디, 비밀번호
- **출력**: JWT 토큰, 계정 정보(이름, 역할, 정비소명)
- **규칙**
  - 토큰에는 계정 번호·`shop_id`·역할이 들어 있다. 이후 모든 정비소 API는 토큰의 `shop_id`로만 조회한다.
  - 실패는 "아이디 없음"과 "비밀번호 틀림"을 같은 응답으로(`LOGIN_FAILED`).
  - 토큰이 없거나 만료되면 401 → 화면은 로그인으로 이동. 토큰 유효 시간 💡 12시간.
  - 로그아웃은 화면에서 토큰을 지운다. 서버 강제 무효화는 P2.
  - 정지된 정비소의 계정은 로그인 불가 (P1, F-ADM-02).
- **완료 기준**: 시드 사장·정비사로 로그인 → 홈 진입. 잘못된 비밀번호 → 같은 실패 문구. 토큰 없이 정비소 API → 401(X10).

### F-AUTH-02 서비스 관리자 로그인 (P0-핵심)

- **입력**: 아이디, 비밀번호 → **출력**: 서비스 관리자 토큰(`shop_id` 없음, 역할 ADMIN)
- **규칙**: 서비스 관리자 계정은 `platform_admin` 표에만 있다. 서비스 관리자 토큰은 `/api/admin/**`만 허용, 정비소 API는 403(D-07). P0에는 관리 화면이 없다(로그인 화면의 "관리자 로그인" 전환은 💡 P1에서 S-10과 함께).
- **완료 기준**: 시드 서비스 관리자 토큰으로 고객 목록(API-05) → 403(X9).

### F-AUTH-03 첫 로그인 비밀번호 변경 (P1)

- 서비스 관리자(또는 사장)가 발급한 임시 비밀번호 계정(`password_change_required`)은 로그인 직후 비밀번호 변경 전까지 다른 API를 쓸 수 없다(💡 `PASSWORD_CHANGE_REQUIRED`).

## 3. 홈

### F-HOME-01 홈 (P0-핵심, D-39)

- **출력**
  - 요약 숫자 1: **오늘 예약 N건** — 오늘 날짜 예약 중 취소를 뺀 건수(💡)
  - 요약 숫자 2: **오늘 연락할 고객 N명** — 안내 수신 동의 고객 중 도래·임박 항목이 있는 차량을 가진 고객 수. 그 차량이 모두 "예약 있음"이면 세지 않음. 누르면 S-04
  - 오늘 예약 목록: 시각 순. 시각·차량번호·고객명·예약 목적·상태(·처리 필요). 날짜 앞뒤 이동은 F-RSV-02, P0-나머지부터 목록 자리에 캘린더(F-RSV-05). 고르면 예약 상세 패널(F-RSV-03)
  - (P1) 홈 하단 "고객 집계" 카드(F-STAT-01, 사장·정비사 공통)
- **완료 기준**: 시드 기준 두 숫자가 07 시드 구성의 기대값과 같다. 예약을 하나 등록하면 해당 고객이 "오늘 연락할 고객"에서 빠진다.

## 4. 고객·차량

### F-CUS-01 고객·차량 검색 (P0-핵심)

- **입력**: 검색어 하나(차량번호·연락처·고객명 일부) 💡
- **출력**: 고객 목록(고객명, 연락처, 동의, 차량번호들). 차량번호 중복이 있으면 그대로 여러 건
- **규칙**: 로그인한 정비소의 고객만. 신규 등록 전에 먼저 조회한다(등록 화면에서 같은 검색을 보여줌). 목록 연락처는 P0-나머지부터 마스킹(F-CUS-07).

### F-CUS-02 신규 고객·차량 등록 (P0-핵심)

- **입력**: 고객명(필수), 연락처(필수), 안내 수신 동의(기본 미체크, D-11), 차량번호(필수), 차종(필수), 연식·현재 주행거리(선택. 주행거리는 0 이상 정수)
- **규칙**
  - 고객과 첫 차량을 한 번에 만든다. 차량번호 중복은 막지 않는다.
  - 연식·주행거리가 비어 있으면 정비 시작 때 필수다(F-RSV-09·F-MNT-01, D-58).
  - 같은 연락처 또는 같은 차량번호의 기존 고객이 있으면 등록 화면 위에 보여주고 ① 기존 고객 선택(차량만 추가) ② 그래도 새로 등록(가족 공동 번호는 막지 않음)을 고르게 한다. F-CUS-06이 만들어지면(P0-나머지) ③ "기존 고객 수정" 링크를 안내창에 더한다.
  - 연락처 형식은 숫자·하이픈만 💡, 차량번호는 형식 검사 없이 공백만 제거 💡.
  - 주민번호·주소 등은 받지 않는다.
- **완료 기준**: 전화 예약 중(M-02 안에서)과 현장(S-05) 모두에서 등록할 수 있다. 등록 직후 차량 상태는 6개 항목 모두 미확인.

### F-CUS-03 기존 고객에 차량 추가 (P0-핵심)

- **입력**: 차량번호(필수), 차종(필수), 연식·주행거리(선택. 주행거리는 0 이상 정수). 고객을 새로 만들지 않는다. 연식·주행거리가 비어 있으면 정비 시작 때 필수(D-58).

### F-CUS-04 고객 상세 (P0-핵심)

- **출력**: 고객 정보(전체 연락처, D-40), 동의, 차량 목록(차량번호·차종·각 차량에 도래·임박 항목 수)

### F-CUS-05 차량 상세 (P0-핵심)

- **출력**: 차량·고객 정보, 6개 항목의 점검 주기 상태(기준 기록일·다음 정비일·근거), 방문 단위 정비 이력(최신순, 페이지)
- **규칙**: 상태는 F-CYC-01 결과 그대로. 정상·불량 표현을 쓰지 않는다. P0-나머지부터 "지난 방문 거절"·"지난 점검 주의", P1부터 약식 도면(F-CUS-08)·월평균 반영(F-CYC-03).

### F-CUS-06 고객·차량 기본 수정 (P0-나머지)

- 고객: 고객명·연락처·안내 수신 동의. 차량: 차량번호·차종·연식·**최근 주행거리**(차종은 비울 수 없고, 연식·최근 주행거리도 값이 있으면 비울 수 없음).
- 동의를 해제하면 그 고객은 재점검 대상과 홈 숫자에서 즉시 빠진다. 동의·철회 이력은 P2.
- 삭제·비활성화는 F-CUS-10(P1).

### F-CUS-07 목록 연락처 마스킹 (P0-나머지)

- 목록 화면(S-02 오늘 예약·캘린더 목록, S-04, S-05)의 연락처를 💡 `010-****-0001` 형식으로. 서버가 마스킹한 값을 내려준다. 상세 화면(S-06·S-07·예약 상세 패널)과 문자 초안(P1)은 전체 번호(D-40).

### F-CUS-08 차량 약식 도면 (P1, D-33)

- 차량 상세에 일반 약식 도면(특정 제조사 그림이 아닌 것)을 두고, 6개 항목 위치에 점검 주기 상태 색을 표시한다. 색은 `StatusBadge`와 같은 기준. 입력·수정·저장 없음. 상태는 API-10 응답 그대로.

### F-CUS-09 고객 단위 지표 (P1, 화면: S-05 목록 줄·S-06 상단 요약, D-59)

- 고객별로 보여준다. **최근 방문**(그 고객 차량들의 가장 늦은 방문일), **방문 횟수**(서로 다른 방문의 수, 예약 없이 온 방문 포함), **점검 예정**(도래·임박 항목이 있는 차량 보유 — 동의와 무관하게 표시, 연락 목록만 동의 고객).
- **"방문"의 정의는 F-STAT-01에 한 곳으로 둔다.** 여기서는 그 정의를 그대로 쓴다(외부 기록만 있는 방문은 최근 방문·방문 횟수에서 제외).
- 새 저장 없음. 05·07 응답에 `lastVisitDate`·`visitCount`·`hasUpcomingCheck`를 더한다. 5년 경과로 익명화된 고객(F-CUS-11)은 제외. 기간별 신규·재방문 집계는 F-STAT-01.

### F-CUS-10 고객·차량 비활성화·삭제 (P1, 사장, D-56)

> **구현 착수 조건**: 이 기능은 문서로 확정하되, 구현 이슈는 05 POL-46(법적 근거 확인, 담당 PM, 시한 💡 M3 MVP 검증 전) 확인이 끝난 뒤에 연다.

- **고객**: 이력(정비 기록·예약)이 **없으면** 삭제(이력 없는 차량도 함께), **있으면** 비활성화. 유효 예약이 있는 차량이 있으면 비활성화 불가(409 `HAS_ACTIVE_RESERVATION`). 이력이 있는 고객을 삭제하려 하면 409 `HAS_HISTORY`.
- **차량**: 영구 보존이라 물리 삭제는 없고 비활성화만(유효 예약이 있으면 불가). 이력 없는 차량은 이력 없는 고객을 삭제할 때만 함께 지워진다.
- **비활성 고객·차량**: 검색에서 기본 제외(`includeInactive`로 포함), 재점검 대상·홈 "오늘 연락할 고객"에서 제외, 새 예약·정비 기록 불가(400 `INVALID_INPUT`), 기존 기록은 조회 가능. 비활성 고객의 차량은 고객 상태를 따른다(별도 연쇄 저장 없이 조회에서 걸러냄). 사장이 재활성화할 수 있다.
- **권한**: 사장만. 정비사는 403 `FORBIDDEN`(K8).
- **완료 기준**: K1~K5, K8, K9.

### F-CUS-11 보관 기간 경과 고객 파기 (P1, 사장, D-56)

> **구현 착수 조건**: F-CUS-10과 같다. 05 POL-46(법적 근거 확인, 담당 PM, 시한 💡 M3 MVP 검증 전) 확인이 끝난 뒤에 구현 이슈를 연다.

- **기준일** = 그 고객 차량들의 마지막 방문일(외부 기록만 있는 방문 제외), 방문이 없으면 고객 등록일. 기준일 + 5년 ≤ 오늘이면 "보관 기간 경과" 목록(설정 S-09 탭)에 나온다.
- 사장이 목록에서 확인하고 **익명화**를 실행한다(자동 아님, 서버 스케줄러 없음). 5년이 지나지 않았으면 409 `RETENTION_NOT_REACHED`, 유효 예약이 있으면 409 `HAS_ACTIVE_RESERVATION`.
- **익명화**: 이름을 "(삭제된 고객)", 연락처를 빈 값, 동의를 해제하고 `anonymized_at`을 기록한다. 되돌릴 수 없다. 차량과 정비 이력·예약은 보존한다. 재점검 대상·지표에서 빠진다.
- 법적 근거(차량번호·정비 이력의 영구 보존 등)는 05 POL-46에 따른다.
- **완료 기준**: K6, K7, K8, K9.

## 5. 정비 기록·방문 중 안내

### F-MNT-01 방문·정비 기록 저장 (P0-핵심)

- **입력**: 방문일(기본 오늘), 주행거리(선택, 0 이상 정수), 항목 1개 이상: 항목·구분(교체/점검)·메모(선택)
- **규칙**
  - 한 번 저장한 항목들은 같은 `visit_key`로 묶인다(D-04). 방문 메모는 따로 없고 항목별 메모만(방문 단위 정보는 P2).
  - 담당 정비사: P0-핵심에서는 저장한 계정 💡. P0-나머지부터 담당 정비사(`mechanicId`)를 요청에서 고르며 기본값은 예약의 담당(예약 완료 후 이동 시) 또는 로그인 계정이다. 정비사도 다른 정비사로 지정할 수 있다(D-51·D-55). 그 정비소의 사장·정비사가 아니면 400 `INVALID_INPUT`(X13).
  - 차량의 연식이나 최근 주행거리가 비어 있고 요청에 교체·점검 항목이 있으면, 요청에 `vehicle.modelYear`·방문 `mileage`를 반드시 넣어야 한다(없으면 400 `INVALID_INPUT`). 같은 트랜잭션에서 차량에 반영한다(D-58). 방문 접수(F-RSV-09)에서 이미 입력했다면 차량에 값이 있으므로 다시 요구하지 않는다.
  - 같은 방문에 같은 항목을 두 번 넣을 수 없다.
  - 방문일은 오늘 이전·오늘만(미래 불가) 💡.
  - 주행거리를 넣으면 차량의 최근 주행거리를 갱신한다(기존 값보다 작으면 경고 없이 저장하되 갱신하지 않음 💡).
  - 저장한 기록은 F-MNT-04로 수정한다(P0-나머지). 삭제는 없다. F-MNT-04 전(P0-핵심)에 잘못 넣었으면 같은 항목을 다시 기록한다.
  - 예약에서 방문 완료(F-RSV-04) 후 들어오면 차량이 채워져 있다. 예약과 기록을 데이터로 잇지는 않는다(화면 이동).
- **완료 기준**: 교체 저장 후 그 항목이 여유로 바뀌고 재점검 대상에서 빠진다. 점검 저장은 상태를 바꾸지 않는다(T12).

### F-MNT-02 외부 정비·거절 기록 (P0-나머지, D-37)

- **외부**: 고객이 다른 곳에서 했다고 진술한 항목. 입력: 항목, 정비일(확인 가능하면), 주행거리(확인 가능하면), 메모. 출처는 "고객 진술". 정비일이 없으면 기록하지 않는다(기준일이 필요) 💡. 주기를 다시 시작한다(T13).
- **거절**: 권유했으나 고객이 거절한 항목. 방문일·메모로 기록. 주기는 그대로(T14).
- 구분값은 P0-핵심부터 정의되어 있고(D-06) 입력 선택지만 이 단계에서 연다.
- 외부 기록의 방문일은 고객이 말한 정비일(과거일 수 있음)이다. F-MNT-04의 수정 기간(3일)은 이 기록에서 저장일 기준으로 센다.

### F-MNT-03 점검 결과 기록 (P0-나머지, D-36)

- 구분이 "점검"인 항목에만 결과 양호/주의(선택)와 메모를 남긴다.
- 결과는 진단이 아니라 정비사의 관찰 기록이다. 주기 상태와 재점검 대상 기준을 바꾸지 않는다.

### F-MNT-04 정비 기록 수정 (P0-나머지, D-55)

- **수정 대상**: 기록 1행. 수정 가능: 방문일(미래 불가)·주행거리(0 이상)·구분·항목(그 정비소의 쓰는 항목)·점검 결과·메모·담당 정비사. 수정 불가: 차량.
- **권한**: 사장은 모든 기록, 기간 제한 없음. 정비사는 **본인이 담당한 기록만, 방문일 기준 3일 이내**(방문일 + 3일 말까지). 외부 기록의 방문일은 고객이 말한 정비일(과거일 수 있음)이므로 **저장일(`created_at`) 기준**으로 센다. 기간을 넘으면 403 `EDIT_PERIOD_EXPIRED`, 담당이 아니면 403 `FORBIDDEN`. 기준은 수정 전 방문일이다.
- **삭제 없음**. 잘못 넣은 기록(다른 차량 등)은 후속(P2)의 "무효 처리"로 다룬다. 그 전에는 구분을 점검·거절로 바꾸고 메모로 남긴다.
- **규칙**: 구분과 출처의 짝(`EXTERNAL` ↔ `CUSTOMER_STATEMENT`)은 서버가 맞춘다. 점검 결과는 구분이 점검일 때만 두고, 구분을 바꾸면 비운다. 같은 방문에 같은 항목 두 번 불가는 수정 후에도 검사한다. 바뀐 필드가 없으면 400 `INVALID_INPUT`. `version` 필수(409 `CONCURRENT_MODIFICATION`).
- **주행거리**: 수정값이 차량 최근 주행거리보다 크면 갱신(05 POL-60), 작으면 갱신하지 않는다. 잘못 큰 값은 차량 수정(F-CUS-06)에서 최근 주행거리를 고친다.
- **이력**: 수정할 때마다 1건 — 수정자·수정 시각·수정 전 값 전체·사유(선택). 화면은 수정 날짜·수정자·바뀐 항목(`항목명: 전 → 후`)을 보여준다.
- **주기 상태**: 저장하지 않으므로 수정 즉시 다음 정비일·상태·재점검 대상에 반영된다.
- **완료 기준**: H1~H11.

## 6. 주기 계산

### F-CYC-01 항목 상태 계산 (P0-핵심)

계산은 백엔드 `domain/cycle` 한 곳에서만 하고, 상태는 저장하지 않는다. 날짜는 `Clock` 기준 오늘.

| 규칙 | 내용 |
|---|---|
| 기준 기록 | 그 항목의 **교체** 또는 **외부** 기록 중 날짜가 가장 늦은 것. 같은 날이면 나중에 저장한 것. 점검·거절은 기준이 아님 |
| 미확인 | 기준 기록이 없음 |
| 다음 정비일 | 기준 기록일 + 주기 개월 (달력 기준 `plusMonths`. 말일은 그 달 말일로) |
| 도래 | 오늘 ≥ 다음 정비일. 또는 방문 때 입력한 주행거리 ≥ 기준 기록 km + 주기 km (기준과 같아도 도래, D-09) |
| 임박 | 도래가 아니고, 오늘 + 1개월 ≥ 다음 정비일 (달력상 1개월, D-08) |
| 여유 | 그 밖 |
| km 판정 생략 | 기준 기록에 주행거리가 없거나, 방문 주행거리를 입력하지 않았을 때 |
| 우선순위 | 도래 > 임박 > 여유. km 판정은 "도래"만 만든다 |
| 사용 여부 | 정비소에서 쓰지 않는 항목은 계산하지 않는다(P0는 6개 모두 사용) |

- 재점검 대상 목록·홈·차량 상세·미리보기·예약 상세 패널·문자 초안(P1)·도면(P1)이 이 결과를 그대로 쓴다.
- P0에서는 km만 넘은 차량이 방문 전 대상 목록에 뜨지 않는다(F-CYC-03에서 보완).

### F-CYC-02 지난 방문 거절·지난 점검 주의 표시 (P0-나머지)

| 표시 | 조건 | 사라지는 때 |
|---|---|---|

두 표시 모두 상태(미확인/여유/임박/도래)를 바꾸지 않는다. 대상 목록에는 이미 대상인 차량에 표시만 붙인다.

### F-CYC-03 월평균 주행거리 추정 (P1 1순위)

- 그 차량의 주행거리 기록이 2회 이상이면 월평균 주행거리 = (최근 기록 km − 가장 오래된 기록 km) ÷ 두 기록 사이 개월 수 💡.
- km 기준 도달 예상일 = 기준 기록일 + (주기 km ÷ 월평균) 개월. 다음 정비일은 기간 기준과 예상일 중 **먼저 오는 날**.
- 기록이 1회 이하이거나 월평균이 0 이하이면 환산하지 않는다.
- 이 날짜로 임박·도래를 판정하므로 방문 전 대상 목록에도 반영된다.

## 7. 재점검 대상

### F-TGT-01 재점검 대상 목록 (P0-핵심)

- **대상**: 안내 수신에 동의한 고객의 차량 중 도래·임박 항목이 하나 이상인 차량(개월 기준, P1부터 월평균 반영). 미확인은 대상이 아니다(방문 때 확인할 항목).
- **표시**: 고객·차량별 한 줄. 항목·상태·근거(기준 기록일·다음 정비일). 도래가 있는 차량 먼저, 그다음 다음 정비일이 이른 순 💡.
- **예약 있음 (D-13)**: 그 차량에 유효 예약(상태 "예약" + 날짜 ≥ 오늘, 또는 "진행중")이 있으면 목록에 남기고 "예약 있음(일시)" 표시. 예약이 취소되면 바로 다시 연락 대상.
- **바로 예약**: 줄에서 예약 등록(M-02, 차량 채워짐).
- P0-나머지부터 "지난 방문 거절"·"지난 점검 주의" 표시(F-CYC-02). P1부터 문자 초안·연락 결과(F-CON-01·02).
- **완료 기준 (시나리오 A)**: 시드 기준 목록이 07의 기대 상태표와 같다. 미동의 고객은 나오지 않는다. 목록에서 예약하면 "예약 있음"이 붙고 홈 숫자가 줄어든다.

## 8. 예약

### F-RSV-01 예약 등록 (P0-핵심)

- **입력**: 차량(검색 또는 신규 등록 후 선택), 날짜, 시각, 예약 목적(선택 입력, D-38): 정비 항목 여러 개 선택 + 기타 + 메모, **담당 정비사**(D-51, 아래 단계 구분)
- **규칙**
  - 시각은 30분 단위(분이 00 또는 30)만(D-21). 소요 시간은 받지 않는다.
  - 날짜는 오늘 이후만. 오늘은 지난 시각도 허용(D-23).
  - 같은 차량에 유효 예약이 있으면 등록 불가(D-22) → 기존 예약을 변경하도록 안내.
  - 같은 시각에 다른 **담당**의 예약은 제한하지 않는다(수용량은 P2).
  - 예약 목적 항목은 그 정비소에서 쓰는 항목만.
- **담당 정비사 — P0-핵심 (스키마·등록자 자동 지정)**: 요청에 담당 필드가 없다. 서버가 예약을 등록한 계정(토큰)을 담당(`assignee_staff_id`, NOT NULL)으로 저장한다. 담당 중복 검사는 하지 않는다.
- **담당 정비사 — P0-나머지부터 (선택·충돌 제한)**
  - 입력에 `담당 정비사`(필수, 기본 = 로그인 계정이 정비사면 본인, 사장이면 사장 본인). 후보는 API 36.
  - 담당은 그 정비소의 사장·정비사만(남의 정비소·없는 id → 400 `INVALID_INPUT`, X13).
  - 같은 담당 + 같은 시작 시각에 유효 예약(예약·진행중)이 있으면 등록 불가 → 409 `MECHANIC_SLOT_CONFLICT`(`details`에 겹친 예약 번호).
  - 같은 시각 다른 담당은 허용. 같은 차량 유효 예약 1건은 유지(D-22).
  - 소요 시간이 없어 10:00 예약은 10:30 예약을 막지 않는다(시작 시각만 비교).
- **예약 규칙 테스트**: R1~R4(P0-핵심), R15~R20(P0-나머지)
- 같은 차량에 유효 예약이 있어 막히면, 서버가 기존 예약 번호를 알려주고 화면은 그 예약의 상세 패널을 열어 확인·변경하게 한다(F-RSV-06).

### F-RSV-02 날짜별 예약 목록 (P0-핵심, 위치는 홈 S-02, D-54)

- 하루 단위로 시각 순. 시각·차량번호·고객명·예약 목적 요약·상태. 상태가 "예약"인데 시각이 지났으면 **처리 필요** 표시(D-23). 취소·노쇼도 상태와 함께 보여준다 💡.

### F-RSV-04 방문 완료 처리 (P0-핵심)

- 상태 "예약" 또는 "진행중"(F-RSV-09, P0-나머지)인 예약만. 시각 전·후 모두 가능(지난 예약도, D-23). 진행중에서 완료해도 S-08로 이동한다.
- 완료 후 화면은 방문·정비 기록(S-08)으로 이동하고 차량이 채워진다. 완료와 기록 저장은 별도 요청이고, 기록이 없어도 완료 상태는 유지된다(05 POL-95).
- 화면이 읽은 예약의 `version`을 함께 보낸다. 다른 직원이 먼저 끝냈거나(`INVALID_STATUS_TRANSITION`) 먼저 바꿨으면(`CONCURRENT_MODIFICATION`) 409로 실패하고 상태를 덮어쓰지 않는다. 화면은 예약 상세 패널을 다시 조회한다(R5·R10·R12·R13, 08 6장).

### F-RSV-05 홈 캘린더 (P0-나머지, D-34·D-54·D-16)

월·주 두 가지만 있다. 일 보기는 없다(D-54로 D-34 수정). 정비소당 공용 캘린더 하나이고 홈(S-02)에 둔다.

- **월 보기**: 날짜별 총 건수(**취소만 제외, 진행중·노쇼는 포함**) + 상태별 작은 숫자(예약·진행중·완료·취소·노쇼). 날짜를 누르면 그날 목록 패널(F-RSV-02 목록), 목록에서 예약을 누르면 상세 패널(F-RSV-03).
- **주 보기**: 7일 × 30분 칸. 표시 시간대 💡 08:00~20:00(그 밖 예약은 맨 위·아래 줄에 모아 표시 💡). 칸 안에 시각·차량번호·고객명 상세 카드. 카드에 담당 색 띠.
- 우측 상단 버튼으로 월/주를 전환한다.
- **담당 색**: 서버가 `colorIndex`를 준다(정비소 안 정비사 계정 id 순서, 비활성 포함, 8색 순환). 색만으로 구분하지 않고 이름 라벨을 함께 보인다. 색은 상태 색(회색·파랑·주황·빨강)과 겹치지 않는 💡 보라·청록·분홍·갈색·연두·남색·올리브·자주.
- "내 담당만" 토글 💡 기본 전체. 보기 필터일 뿐 데이터 권한이 아니다(06).
- 월 집계는 기간 목록(15)이 쪽 나누기라 부족하므로 별도 요약 API 42를 쓴다. 주 보기는 기간 조회 API(15). 고르면 같은 상세 패널. 드래그 이동·반복 예약 없음(P2).

- **완료 기준**: R7·R8·R9·R11·R14, 담당 재배정·중복은 R15~R20(P0-나머지)·R24, 변경 후 "예약 있음"·홈 숫자·날짜별 목록이 바뀐 일시로 보인다.

### F-RSV-07 예약 취소 (P0-나머지)

- 상태 "예약" 또는 "진행중"만. 시각 전·후 모두 가능. 취소 사유는 받지 않는다 💡. 동시 수정은 방문 완료와 같다(`version`, R10·R12·R13).

### F-RSV-08 노쇼 처리 (P0-나머지, D-27)

- 상태 "예약"이고 시각이 지난 예약만(진행중은 노쇼 불가). 자동 처리·노쇼 횟수·경고·통계는 P2. 동시 수정은 방문 완료와 같다(`version`, R10·R12·R13).

### F-RSV-09 방문 접수 (P0-나머지, D-52)

- 상태 "예약"인 예약을 "진행중"으로 바꾼다(차량 도착). 시각 전·후 모두 가능(D-23). 방문과 진행중을 한 상태로 본다.
- `version` 필수(R5·R10·R12·R13과 같은 동시 수정 규칙).
- 차량의 연식·최근 주행거리가 비어 있으면 같은 요청에 `modelYear`·`mileage`를 받아 차량에 저장한다(D-58). 없으면 400.
- 접수 후에도 정비 기록은 별도 저장이다(05 POL-95 그대로). 예약 → 완료 직접 전이도 허용한다(F-RSV-04).
- 진행중이 되면 변경(19)·재배정은 불가하고 완료·취소만 가능하다. 담당의 시작 시각을 계속 점유한다(R22).
- **완료 기준**: R21~R23.

### F-RSV-10 지난 예약 정정 (P0-나머지, D-53)

- **대상**: 상태가 완료·취소·노쇼인 예약, 또는 예약 날짜 < 오늘인 예약(메모만). 이런 예약은 일시·고객·차량·담당을 바꿀 수 없고 상태·메모만 정정한다.

| 현재 → 정정 | 허용 | 권한 |
|---|---|---|
| 취소 ↔ 노쇼 | ○ | 사장 |
| 취소·노쇼 → 완료 | ○ (정비 기록은 자동 생성 안 함, 별도 입력) | 사장 |
| 완료 → 취소·노쇼 | × 409 `INVALID_STATUS_TRANSITION` | — |
| 메모(`purposeMemo`) 정정 | ○ | 사장 / 담당 정비사(예약 날짜 + 3일 이내) |

- 정정 사유는 선택. 모든 정정은 `reservation_revision`에 남고 `version`이 오른다.
- 정비사가 기간을 넘으면 403 `EDIT_PERIOD_EXPIRED`, 담당이 아니면 403 `FORBIDDEN`. 사장은 제한이 없다.
- 상태 "예약"인 처리 필요 예약의 정리(완료·취소·노쇼)는 정정이 아니라 기존 F-RSV-04·07·08(18·20·21)이다.
- **완료 기준**: R25~R29.

## 9. 연락·알림 (P1)

### F-CON-01 문자 초안

- 대상 목록의 고객 1명당 문자 1개(여러 차량·항목을 묶고 도래 먼저). 고정 템플릿 1종, 변수: 정비소명·고객명·차량번호·항목·상태·마지막 기록일·정비소 연락처. 정비 시기 안내만(홍보 문구 없음).
- PC는 "복사", 폰·태블릿은 "문자 앱 열기"(한 명씩). 차곡은 발송하지 않는다.
- 동의 고객만. 전체 번호를 보여준다(발송용).

### F-CON-02 연락 결과 기록

- 결과 6개(D-59): 예약함(`RESERVED`) · 부재(`ABSENT`) · 이미 정비함(`ALREADY_DONE`) · 연락함(`CONTACTED`) · 번호 오류(`WRONG_NUMBER`) · 연락 거부(`REFUSED`).
- "연락 거부"를 고르면 "안내 수신 동의를 해제할까요?" 확인 대화상자를 띄운다. 자동 해제가 아니며, 해제하면 05 POL-35대로 즉시 대상에서 빠진다.
- 기록한 고객은 목록에 남고 "연락함(날짜)" 꼬리표를 30일(💡) 보여준 뒤 사라진다(대상 목록에는 계속 있음). 번호 오류·연락 거부는 꼬리표만 남긴다.
- "예약함" → 예약 등록(M-02), "이미 정비함" → 외부 정비 기록(F-MNT-02 화면 재사용).
- 정비사도 기록할 수 있다(D-57).

### F-NTF-01 사장 아침 알림

- 사장이 시간을 고르고 브라우저 알림을 허용. 탭이 열려 있는 동안 하루 1회 "오늘 연락할 고객 N명"(0명이면 생략), 누르면 S-04. 서버 스케줄러 없음. 알림 시간과 허용 여부는 **브라우저(localStorage)에 저장**한다. 서버·DB·API가 없다(다른 기기에서는 다시 설정, D-59).

## 10. 서비스 관리자·설정 (P1)

### F-ADM-01 정비소 개설

- 서비스 관리자가 정비소(이름·연락처)를 만들고 사장 계정(아이디·임시 비밀번호)을 발급. 정비소 목록(이름·상태·생성일)만 조회. 정비소 안의 고객·차량·이력·예약 수는 보지 않는다.
- 새 정비소에는 6개 항목 기준표(D-01)를 기본으로 넣는다 💡.

### F-ADM-02 이용 정지·재개, 사장 비밀번호 재설정

- 정지: 그 정비소 계정의 로그인만 막고 데이터는 유지(이미 발급된 토큰 차단은 P2). 재개: 다시 로그인 가능.
- 사장 비밀번호 분실 시 임시 비밀번호 재발급만(기존 비밀번호 확인 불가).

### F-STF-01 정비사 계정 추가·비활성화 (사장, D-57)

- 아이디·이름·임시 비밀번호로 추가(삭제 없음). 정비사는 첫 로그인 때 변경(F-AUTH-03 💡 정비사에도 적용).
- **비활성화**: 사장만, 그 정비사가 담당한 **유효 예약이 없을 때만**(있으면 409 `HAS_ACTIVE_RESERVATION`, 사장이 먼저 재배정). 사장 본인은 비활성화 불가(400).
- 비활성 정비사는 로그인할 수 없고(403 `ACCOUNT_INACTIVE`) 담당 후보에서 빠지지만, 과거 예약·기록의 담당 이름은 남는다.
- **완료 기준**: K10.

### F-ITEM-01 항목·기준표 설정 (사장, D-57)

- 정비소가 쓰는 항목 켜기·끄기, 개월·km 수정. 바꾸면 모든 상태 계산에 바로 반영(상태를 저장하지 않으므로 이관 없음). 새 항목 추가는 하지 않는다(P2). 6개 항목의 켜기·끄기, 개월·km 수정만 한다(D-59).

### F-STAT-01 신규·재방문 고객 집계 (P1, 화면: 홈 S-02 하단 "고객 집계" 카드, D-59)

- 기간별 신규 등록 고객 수, 재방문 고객 수. 기간은 이번 달·지난달·직접 선택. 사장·정비사 공통.
- **방문·재방문의 정의는 여기 한 곳에만 둔다.** 05 POL-45와 F-CUS-09는 이 정의를 가리킨다.
  - **방문** = `visit_key` 하나. 외부 정비 기록만 있는 방문은 방문으로 세지 않는다(방문 횟수·최근 방문·5년 기준일에서 제외).
  - **재방문 고객** = 그 기간에 방문 기록이 있고, 그 이전에도 방문 기록이 있는 고객.
