# 04 기능 명세서

> 기능 ID·입력·출력·규칙·완료 기준 — **기능 ID, 기능 규칙, 주기 규칙, 테스트 ID(T-xx·R-xx)의 원본**

상태: 작성됨 (2026-11-22 · @하다) — 관문 1에서 확정
근거: 00 PRD(단계), 상세 기획안 v11, 결정 D-01~D-39
단계는 00이 원본이다. API 번호는 08, 테이블은 07, 화면 ID는 09를 따른다. 💡 = 제안값(관문 1에서 확정).

## 0. 표기

- 기능 ID: `F-영역-번호`. 영역: AUTH 인증, HOME 홈, CUS 고객·차량, MNT 정비 기록, VIS 방문 중 안내, CYC 주기 계산, TGT 재점검 대상, RSV 예약, CON 연락, NTF 알림, ADM 관리자, STF 정비사 계정, ITEM 항목 기준표, STAT 집계
- 역할: 사장(OWNER) · 정비사(MECHANIC) · 서비스 관리자(ADMIN). 사장과 정비사는 설정을 뺀 모든 업무가 같다(D-24, 06)
- 테스트 ID: T-xx 주기 계산(백엔드 `test/.../cycle`), R-xx 예약 규칙, X-xx 정비소 격리(08)
- 상태 용어: 점검 주기 상태 = 미확인/여유/임박/도래. 예약 상태 = 예약/방문 완료/취소/노쇼

## 2. 인증

### F-AUTH-01 사장·정비사 로그인·로그아웃 (P0-핵심)

- **입력**: 아이디, 비밀번호
- **출력**: JWT 토큰, 계정 정보(이름, 역할, 정비소명)
- **규칙**
  - 토큰에는 계정 번호·`shop_id`·역할이 들어 있다. 이후 모든 정비소 API는 토큰의 `shop_id`로만 조회한다.
  - 실패는 "아이디 없음"과 "비밀번호 틀림"을 같은 응답으로(`LOGIN_FAILED`).
  - 토큰이 없거나 만료되면 401 → 화면은 로그인으로 이동. 토큰 유효 시간 💡 12시간.
  - 로그아웃은 화면에서 토큰을 지운다. 서버 강제 무효화는 P2.
  - 정지된 정비소의 계정은 로그인 불가 (P1, F-ADM-02).
- **완료 기준**: 시드 사장·정비사로 로그인 → 홈 진입. 잘못된 비밀번호 → 같은 실패 문구. 토큰 없이 정비소 API → 401(X10).

### F-AUTH-02 서비스 관리자 로그인 (P0-핵심)

- **입력**: 아이디, 비밀번호 → **출력**: 관리자 토큰(`shop_id` 없음, 역할 ADMIN)
- **규칙**: 관리자 계정은 `platform_admin` 표에만 있다. 관리자 토큰은 `/api/admin/**`만 허용, 정비소 API는 403(D-07). P0에는 관리 화면이 없다(로그인 화면의 "관리자 로그인" 전환은 💡 P1에서 S-10과 함께).
- **완료 기준**: 시드 관리자 토큰으로 고객 목록(API-05) → 403(X9).

### F-AUTH-03 첫 로그인 비밀번호 변경 (P1)

- 관리자가 발급한 임시 비밀번호 계정(`password_change_required`)은 로그인 직후 비밀번호 변경 전까지 다른 API를 쓸 수 없다(💡 `PASSWORD_CHANGE_REQUIRED`).

## 3. 홈

### F-HOME-01 홈 (P0-핵심, D-39)

- **출력**
  - 요약 숫자 1: **오늘 예약 N건** — 오늘 날짜 예약 중 취소를 뺀 건수(💡)
  - 요약 숫자 2: **오늘 연락할 고객 N명** — 안내 수신 동의 고객 중 도래·임박 항목이 있는 차량을 가진 고객 수. 그 차량이 모두 "예약 있음"이면 세지 않음. 누르면 S-04
  - 오늘 예약 목록: 시각 순. 시각·차량번호·고객명·예약 목적·상태(·처리 필요). 고르면 예약 상세 패널(F-RSV-03)
- **완료 기준**: 시드 기준 두 숫자가 07 시드 구성의 기대값과 같다. 예약을 하나 등록하면 해당 고객이 "오늘 연락할 고객"에서 빠진다.

## 4. 고객·차량

### F-CUS-01 고객·차량 검색 (P0-핵심)

- **입력**: 검색어 하나(차량번호·연락처·고객명 일부) 💡
- **출력**: 고객 목록(고객명, 연락처, 동의, 차량번호들). 차량번호 중복이 있으면 그대로 여러 건
- **규칙**: 로그인한 정비소의 고객만. 신규 등록 전에 먼저 조회한다(등록 화면에서 같은 검색을 보여줌). 목록 연락처는 P0-나머지부터 마스킹(F-CUS-07).

### F-CUS-02 신규 고객·차량 등록 (P0-핵심)

- **입력**: 고객명(필수), 연락처(필수), 안내 수신 동의(기본 미체크, D-11), 차량번호(필수), 차종·연식·현재 주행거리(선택)
- **규칙**
  - 고객과 첫 차량을 한 번에 만든다. 차량번호 중복은 막지 않는다.
  - 연락처 형식은 숫자·하이픈만 💡, 차량번호는 형식 검사 없이 공백만 제거 💡.
  - 주민번호·주소 등은 받지 않는다.
- **완료 기준**: 전화 예약 중(M-02 안에서)과 현장(S-05) 모두에서 등록할 수 있다. 등록 직후 차량 상태는 6개 항목 모두 미확인.

### F-CUS-03 기존 고객에 차량 추가 (P0-핵심)

- **입력**: 차량번호(필수), 차종·연식·주행거리(선택). 고객을 새로 만들지 않는다.

### F-CUS-04 고객 상세 (P0-핵심)

- **출력**: 고객 정보(전체 연락처, D-40), 동의, 차량 목록(차량번호·차종·각 차량에 도래·임박 항목 수)

### F-CUS-05 차량 상세 (P0-핵심)

- **출력**: 차량·고객 정보, 6개 항목의 점검 주기 상태(기준 기록일·다음 정비일·근거), 방문 단위 정비 이력(최신순, 페이지)
- **규칙**: 상태는 F-CYC-01 결과 그대로. 정상·불량 표현을 쓰지 않는다. P0-나머지부터 "지난 방문 거절"·"지난 점검 주의", P1부터 약식 도면(F-CUS-08)·월평균 반영(F-CYC-03).

### F-CUS-06 고객·차량 기본 수정 (P0-나머지)

- 고객: 고객명·연락처·안내 수신 동의. 차량: 차량번호·차종·연식.
- 동의를 해제하면 그 고객은 재점검 대상과 홈 숫자에서 즉시 빠진다. 동의·철회 이력은 P2.
- 삭제 기능은 없다(00 범위 밖).

### F-CUS-07 목록 연락처 마스킹 (P0-나머지)

- 목록 화면(S-02 오늘 예약, S-03, S-04, S-05)의 연락처를 💡 `010-****-0001` 형식으로. 서버가 마스킹한 값을 내려준다. 상세 화면(S-06·S-07·예약 상세 패널)과 문자 초안(P1)은 전체 번호(D-40).

### F-CUS-08 차량 약식 도면 (P1, D-33)

- 차량 상세에 일반 약식 도면(특정 제조사 그림이 아닌 것)을 두고, 6개 항목 위치에 점검 주기 상태 색을 표시한다. 색은 `StatusBadge`와 같은 기준. 입력·수정·저장 없음. 상태는 API-10 응답 그대로.

## 5. 정비 기록·방문 중 안내

### F-MNT-01 방문·정비 기록 저장 (P0-핵심)

- **입력**: 방문일(기본 오늘), 주행거리(선택, 0 이상 정수), 항목 1개 이상: 항목·구분(교체/점검)·메모(선택)
- **규칙**
  - 한 번 저장한 항목들은 같은 `visit_key`로 묶인다(D-04). 방문 메모는 따로 없고 항목별 메모만(방문 단위 정보는 P2).
  - 담당 정비사는 저장한 계정 💡.
  - 같은 방문에 같은 항목을 두 번 넣을 수 없다.
  - 방문일은 오늘 이전·오늘만(미래 불가) 💡.
  - 주행거리를 넣으면 차량의 최근 주행거리를 갱신한다(기존 값보다 작으면 경고 없이 저장하되 갱신하지 않음 💡).
  - 저장한 기록은 수정·삭제하지 않는다(기록 정정은 P2). 잘못 넣었으면 같은 항목을 다시 기록한다.
  - 예약에서 방문 완료(F-RSV-04) 후 들어오면 차량이 채워져 있다. 예약과 기록을 데이터로 잇지는 않는다(화면 이동).
- **완료 기준**: 교체 저장 후 그 항목이 여유로 바뀌고 재점검 대상에서 빠진다. 점검 저장은 상태를 바꾸지 않는다(T12).

### F-MNT-02 외부 정비·거절 기록 (P0-나머지, D-37)

- **외부**: 고객이 다른 곳에서 했다고 진술한 항목. 입력: 항목, 정비일(확인 가능하면), 주행거리(확인 가능하면), 메모. 출처는 "고객 진술". 정비일이 없으면 기록하지 않는다(기준일이 필요) 💡. 주기를 다시 시작한다(T13).
- **거절**: 권유했으나 고객이 거절한 항목. 방문일·메모로 기록. 주기는 그대로(T14).
- 구분값은 P0-핵심부터 정의되어 있고(D-06) 입력 선택지만 이 단계에서 연다.

### F-MNT-03 점검 결과 기록 (P0-나머지, D-36)

- 구분이 "점검"인 항목에만 결과 양호/주의(선택)와 메모를 남긴다.
- 결과는 진단이 아니라 정비사의 관찰 기록이다. 주기 상태와 재점검 대상 기준을 바꾸지 않는다.

### F-VIS-01 방문 중 안내 — 저장 전 미리보기 (P0-핵심, D-10)

- **입력**: 차량, 주행거리(입력하는 즉시)
- **출력**: 6개 항목의 점검 주기 상태(날짜 기준 + 입력한 km 기준), 근거(기준 기록일·기준 km·다음 정비일·기준 km + 주기 km)
- **규칙**: 기록을 남기지 않는다. 주행거리를 비우면 날짜 기준만(T11). "확인이 필요한 항목"으로 안내하고 진단 표현을 쓰지 않는다.
- **완료 기준 (시나리오 B)**: 시드 차량에 주행거리를 넣으면 개월로는 여유인 항목이 km 기준으로 "도래"가 된다(T8).

## 6. 주기 계산

### F-CYC-01 항목 상태 계산 (P0-핵심)

계산은 백엔드 `domain/cycle` 한 곳에서만 하고, 상태는 저장하지 않는다. 날짜는 `Clock` 기준 오늘.

| 규칙 | 내용 |
|---|---|
| 기준 기록 | 그 항목의 **교체** 또는 **외부** 기록 중 날짜가 가장 늦은 것. 같은 날이면 나중에 저장한 것. 점검·거절은 기준이 아님 |
| 미확인 | 기준 기록이 없음 |
| 다음 정비일 | 기준 기록일 + 주기 개월 (달력 기준 `plusMonths`. 말일은 그 달 말일로) |
| 도래 | 오늘 ≥ 다음 정비일. 또는 방문 때 입력한 주행거리 ≥ 기준 기록 km + 주기 km (기준과 같아도 도래, D-09) |
| 임박 | 도래가 아니고, 오늘 + 1개월 ≥ 다음 정비일 (달력상 1개월, D-08) |
| 여유 | 그 밖 |
| km 판정 생략 | 기준 기록에 주행거리가 없거나, 방문 주행거리를 입력하지 않았을 때 |
| 우선순위 | 도래 > 임박 > 여유. km 판정은 "도래"만 만든다 |
| 사용 여부 | 정비소에서 쓰지 않는 항목은 계산하지 않는다(P0는 6개 모두 사용) |

- 재점검 대상 목록·홈·차량 상세·미리보기·예약 상세 패널·문자 초안(P1)·도면(P1)이 이 결과를 그대로 쓴다.
- P0에서는 km만 넘은 차량이 방문 전 대상 목록에 뜨지 않는다(F-CYC-03에서 보완).

### F-CYC-02 지난 방문 거절·지난 점검 주의 표시 (P0-나머지)

| 표시 | 조건 | 사라지는 때 |
|---|---|---|
| 지난 방문 거절(날짜) | 그 항목의 가장 최근 기록이 거절이고, 기준 기록보다 늦음 | 같은 항목이 다시 기록됨 |
| 지난 점검 주의(날짜, 메모) | 그 항목의 가장 최근 기록이 점검이고 결과가 주의 | 같은 항목이 다시 기록됨 (교체·점검·외부·거절) |

두 표시 모두 상태(미확인/여유/임박/도래)를 바꾸지 않는다. 대상 목록에는 이미 대상인 차량에 표시만 붙인다.

### F-CYC-03 월평균 주행거리 추정 (P1 1순위)

- 그 차량의 주행거리 기록이 2회 이상이면 월평균 주행거리 = (최근 기록 km − 가장 오래된 기록 km) ÷ 두 기록 사이 개월 수 💡.
- km 기준 도달 예상일 = 기준 기록일 + (주기 km ÷ 월평균) 개월. 다음 정비일은 기간 기준과 예상일 중 **먼저 오는 날**.
- 기록이 1회 이하이거나 월평균이 0 이하이면 환산하지 않는다.
- 이 날짜로 임박·도래를 판정하므로 방문 전 대상 목록에도 반영된다.

## 7. 재점검 대상

### F-TGT-01 재점검 대상 목록 (P0-핵심)

- **대상**: 안내 수신에 동의한 고객의 차량 중 도래·임박 항목이 하나 이상인 차량(개월 기준, P1부터 월평균 반영). 미확인은 대상이 아니다(방문 때 확인할 항목).
- **표시**: 고객·차량별 한 줄. 항목·상태·근거(기준 기록일·다음 정비일). 도래가 있는 차량 먼저, 그다음 다음 정비일이 이른 순 💡.
- **예약 있음 (D-13)**: 그 차량에 진행 중 예약(상태 "예약" + 날짜가 오늘 이후)이 있으면 목록에 남기고 "예약 있음(일시)" 표시. 예약이 취소되면 바로 다시 연락 대상.
- **바로 예약**: 줄에서 예약 등록(M-02, 차량 채워짐).
- P0-나머지부터 "지난 방문 거절"·"지난 점검 주의" 표시(F-CYC-02). P1부터 문자 초안·연락 결과(F-CON-01·02).
- **완료 기준 (시나리오 A)**: 시드 기준 목록이 07의 기대 상태표와 같다. 미동의 고객은 나오지 않는다. 목록에서 예약하면 "예약 있음"이 붙고 홈 숫자가 줄어든다.

## 8. 예약

### F-RSV-01 예약 등록 (P0-핵심)

- **입력**: 차량(검색 또는 신규 등록 후 선택), 날짜, 시각, 예약 목적(선택 입력, D-38): 정비 항목 여러 개 선택 + 기타 + 메모
- **규칙**
  - 시각은 30분 단위(분이 00 또는 30)만(D-21). 소요 시간은 받지 않는다.
  - 날짜는 오늘 이후만. 오늘은 지난 시각도 허용(D-23).
  - 같은 차량에 진행 중 예약이 있으면 등록 불가(D-22) → 기존 예약을 변경하도록 안내.
  - 같은 시각에 다른 차량 예약은 제한하지 않는다(수용량은 P2).
  - 예약 목적 항목은 그 정비소에서 쓰는 항목만.
- **예약 규칙 테스트**: R1~R4
- 같은 차량에 진행 중 예약이 있어 막히면, 서버가 기존 예약 번호를 알려주고 화면은 그 예약의 상세 패널을 열어 확인·변경하게 한다(F-RSV-06).

### F-RSV-02 날짜별 예약 목록 (P0-핵심)

- 하루 단위로 시각 순. 시각·차량번호·고객명·예약 목적 요약·상태. 상태가 "예약"인데 시각이 지났으면 **처리 필요** 표시(D-23). 취소·노쇼도 상태와 함께 보여준다 💡.
- 날짜를 앞뒤로 넘길 수 있다. 고르면 예약 상세 패널.

### F-RSV-03 예약 상세 패널 (P0-핵심, D-35·D-26)

| 영역 | 내용 |
|---|---|
| 예약 | 일시, 상태(·처리 필요), 예약 목적(고른 항목·기타·메모) |
| 고객·차량 | 고객명, 연락처(전체, D-40), 차량번호, 차종·연식, 최근 주행거리 |
| 최근 정비 이력 | 최근 방문 3회(방문 단위: 날짜·항목·구분·결과·메모). 더 있으면 "전체 이력" → S-07 |
| 점검 주기 요약 | 6개 항목 상태(F-CYC-01). 예약 목적으로 고른 항목은 강조. P0-나머지부터 "지난 방문 거절"·"지난 점검 주의(메모)" |
| 다음 작업 | 방문 완료(F-RSV-04), 변경(F-RSV-06), 취소·노쇼(P0-나머지) |

- 화면 폭 1024px 이상은 목록·캘린더 오른쪽 패널, 미만은 전체 폭 덮개(닫기·뒤로 가기로 복귀).
- 정상·불량 같은 단정 표현을 쓰지 않는다.

### F-RSV-04 방문 완료 처리 (P0-핵심)

- 상태 "예약"인 예약만. 시각 전·후 모두 가능(지난 예약도, D-23).
- 완료 후 화면은 방문·정비 기록(S-08)으로 이동하고 차량이 채워진다. 완료와 기록 저장은 별도 요청이고, 기록이 없어도 완료 상태는 유지된다(05 POL-95).
- 다른 직원이 먼저 끝냈거나 동시에 바꾸면 409로 실패하고 상태를 덮어쓰지 않는다(R5·R10, 08 6장).

### F-RSV-05 예약 캘린더 (P0-나머지, D-34·D-16)

- 월 보기: 날짜별 예약 건수(취소 제외 💡). 날짜를 누르면 일 보기.
- 주 보기: 7일 × 30분 칸. 표시 시간대 💡 08:00~20:00(그 밖 예약은 맨 위·아래 줄에 모아 표시 💡).
- 일 보기: F-RSV-02와 같은 목록.
- 세 보기 모두 같은 기간 조회 API. 고르면 같은 상세 패널. 드래그 이동·반복 예약 없음(P2).

### F-RSV-06 예약 변경 (P0-핵심, D-42)

| 구분 | 내용 |
|---|---|
| 바꿀 수 있음 | 예약 일시(오늘 이후, 30분 단위), 예약 목적: 정비 항목 선택, 기타, 메모 |
| 바꿀 수 없음 | 고객·차량(바꾸려면 취소 후 새로 등록), 방문 완료·취소·노쇼 상태의 예약 |
| 서버 검증 | 정비소 소유(아니면 404) → 상태 "예약" → 동시 수정(`version`) → 시각·날짜 → 같은 차량 진행 중 1건(자기 자신 제외). 하나라도 어긋나면 아무것도 바꾸지 않는다 |
| 동시 수정 | 화면이 읽은 `version`을 함께 보낸다. 그사이 다른 직원이 먼저 바꿨으면 409 `CONCURRENT_MODIFICATION`, 덮어쓰지 않고 최신 내용을 다시 보여준다 |

- 전화 예약 중 같은 차량의 진행 중 예약을 발견하면(R3), 새로 만들지 않고 그 예약을 열어 변경한다.
- **완료 기준**: R7·R8·R9·R11, 변경 후 "예약 있음"·홈 숫자·날짜별 목록이 바뀐 일시로 보인다.

### F-RSV-07 예약 취소 (P0-나머지)

- 상태 "예약"만. 시각 전·후 모두 가능. 취소 사유는 받지 않는다 💡.

### F-RSV-08 노쇼 처리 (P0-나머지, D-27)

- 상태 "예약"이고 시각이 지난 예약만. 자동 처리·노쇼 횟수·경고·통계는 P2.

| R10 | P0-핵심 | 한 직원이 방문 완료한 뒤 다른 직원이 같은 예약을 방문 완료 / 두 요청이 거의 동시 | 하나만 성공. 나머지는 409(`INVALID_STATUS_TRANSITION` 또는 `CONCURRENT_MODIFICATION`), 상태는 먼저 반영된 것 그대로. P0-나머지부터 취소·노쇼(20·21)도 같은 기대 |
| R11 | P0-핵심 | 예약 목적 항목만 바꾸는 변경(`version` 0) 뒤 같은 `version` 0으로 다시 변경 | 첫 요청 성공(`version` 1), 두 번째 409 `CONCURRENT_MODIFICATION`, 첫 변경 내용 유지 |

진행 중 예약(R3·R4)은 상태 "예약" + 예약 **날짜** ≥ 오늘이다(D-22). 그래서 오늘 시각이 지난 "예약"은 "처리 필요"로 보이지만 진행 중으로 세어, 같은 차량 새 등록은 R3처럼 409다(처리 후 등록).

## 9. 연락·알림 (P1)

### F-CON-01 문자 초안

- 대상 목록의 고객 1명당 문자 1개(여러 차량·항목을 묶고 도래 먼저). 고정 템플릿 1종, 변수: 정비소명·고객명·차량번호·항목·상태·마지막 기록일·정비소 연락처. 정비 시기 안내만(홍보 문구 없음).
- PC는 "복사", 폰·태블릿은 "문자 앱 열기"(한 명씩). 차곡은 발송하지 않는다.
- 동의 고객만. 전체 번호를 보여준다(발송용).

### F-CON-02 연락 결과 기록

- 결과: 예약함 · 부재 · 이미 정비함 · 연락함. "번호 오류"·"연락 거부"를 더할지는 P1 착수 때(D-25 후속) ❓.
- 기록한 고객은 목록에 남고 "연락함(날짜)" 표시. 유지 기간은 P1 착수 때 ❓.
- "예약함" → 예약 등록(M-02), "이미 정비함" → 외부 정비 기록(F-MNT-02 화면 재사용).
- 정비사도 기록할 수 있다(D-24).

### F-NTF-01 사장 아침 알림

- 사장이 시간을 고르고 브라우저 알림을 허용. 탭이 열려 있는 동안 하루 1회 "오늘 연락할 고객 N명"(0명이면 생략), 누르면 S-04. 서버 스케줄러 없음. 저장 위치(브라우저 / `staff`)는 P1 착수 때 ❓.

## 10. 관리자·설정 (P1)

### F-ADM-01 정비소 개설

- 관리자가 정비소(이름·연락처)를 만들고 사장 계정(아이디·임시 비밀번호)을 발급. 정비소 목록(이름·상태·생성일)만 조회. 정비소 안의 고객·차량·이력·예약 수는 보지 않는다.
- 새 정비소에는 6개 항목 기준표(D-01)를 기본으로 넣는다 💡.

### F-ADM-02 이용 정지·재개, 사장 비밀번호 재설정

- 정지: 그 정비소 계정의 로그인만 막고 데이터는 유지(이미 발급된 토큰 차단은 P2). 재개: 다시 로그인 가능.
- 사장 비밀번호 분실 시 임시 비밀번호 재발급만(기존 비밀번호 확인 불가).

### F-STF-01 정비사 계정 추가 (사장)

- 아이디·이름·임시 비밀번호. 정비사는 첫 로그인 때 변경(F-AUTH-03 💡 정비사에도 적용).

### F-ITEM-01 항목·기준표 설정 (사장, D-24)

- 정비소가 쓰는 항목 켜기·끄기, 개월·km 수정. 바꾸면 모든 상태 계산에 바로 반영(상태를 저장하지 않으므로 이관 없음). 6개 밖 새 항목 추가는 ❓(P1 착수 때).

### F-STAT-01 신규·재방문 고객 집계

- 기간별 신규 등록 고객 수, 재방문 고객 수. 재방문의 정의(그 기간에 방문 기록이 있고, 그 이전에도 방문 기록이 있는 고객 💡)와 보여줄 화면 위치는 P1 착수 때 ❓.
