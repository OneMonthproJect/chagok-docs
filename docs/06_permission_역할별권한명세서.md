# 06 역할별 권한 명세서

> 역할·정비소별 접근 권한

상태: 작성됨 (2026-11-22 · @하다)
근거: 04 기능 목록, 08 API 목록(권한 열), 결정 D-07·D-12·D-24
API 번호별 권한은 08이 원본이다. 이 문서는 역할 관점에서 모은다.

---

## 1. 역할

| 역할 | 값 | 계정 위치 | 토큰에 담기는 것 |
|---|---|---|---|
| 정비소 사장 | `OWNER` | `staff` | staffId, shopId, role |
| 정비사 | `MECHANIC` | `staff` | staffId, shopId, role |
| 서비스 관리자 | `ADMIN` | `platform_admin` | adminId, role (**shopId 없음**) |

원칙: **사장과 정비사는 설정을 뺀 모든 업무가 같다**(D-24). **관리자는 정비소를 열고 닫을 뿐 정비소 안을 볼 수 없다**(D-07).

## 3. 데이터 범위

| 역할 | 볼 수 있는 데이터 |
|---|---|
| 사장·정비사 | 자기 정비소의 고객·차량·이력·예약·항목 전부. 다른 정비소 데이터는 존재 여부도 알 수 없음(404) |
| 관리자 | 정비소 목록과 운영 정보(이름·연락처·상태·생성일). 정비소별 고객 수·방문 수 같은 집계도 보지 않음 |

## 4. 거부 응답

| 상황 | 응답 |
|---|---|
| 토큰 없음·만료 | 401 `AUTH_REQUIRED` → 화면은 로그인으로 |
| 관리자 토큰으로 정비소 API | 403 `FORBIDDEN` |
| 사장·정비사 토큰으로 관리자 API | 403 `FORBIDDEN` |
| 정비사가 사장 전용 API (P1) | 403 `FORBIDDEN` |
| 다른 정비소 데이터 | 404 `NOT_FOUND` (권한 문제가 아니라 "없음"으로 답함) |
| 정지된 정비소 로그인 (P1) | 403 `SHOP_SUSPENDED` |

## 5. 지키는 방법

| 장치 | 내용 |
|---|---|
| URL 규칙 | `SecurityConfig` 한 곳: `/api/admin/**` → ADMIN, `/api/**` → OWNER·MECHANIC, 사장 전용(P1) → OWNER. 마지막은 `anyRequest().denyAll()` |
| 서비스 안 | 역할 `if` 분기를 만들지 않는다(CONVENTIONS 4장). 소속 확인은 각 도메인의 `getOwned(shopId, id)` |
| 테스트 | `EndpointGuardTest`(등록 안 된 경로는 닫힘, 관리자는 정비소 API 불가), 08의 X1~X10 |
| 화면 | 사장 전용 메뉴는 정비사에게 보이지 않게 하지만, 막는 것은 서버다 |
