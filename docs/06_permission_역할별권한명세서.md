# 06 역할별 권한 명세서

> 역할·정비소별 접근 권한

상태: 작성됨 (2026-11-22 · @하다), 2026-11-23 D-57로 전체 개정
근거: 04 기능 목록, 08 API 목록(권한 열), 결정 D-07·D-12·D-57(D-24를 대체)·D-51~D-53·D-55·D-56
API 번호별 권한은 08이 원본이다. 이 문서는 역할 관점에서 모은다.

---

## 1. 역할

| 역할 | 값 | 계정 위치 | 토큰에 담기는 것 |
|---|---|---|---|
| 사장 | `OWNER` | `staff` | staffId, shopId, role |
| 정비사 | `MECHANIC` | `staff` | staffId, shopId, role |
| 서비스 관리자 | `ADMIN` | `platform_admin` | adminId, role (**shopId 없음**) |

원칙(D-57): **사장은 정비사가 할 수 있는 모든 일을 하고, 설정·계정·비활성화·삭제·파기를 더 한다.** 캘린더는 정비소 공용이고 둘 다 전체 일정을 본다. **서비스 관리자는 정비소를 열고 닫을 뿐 정비소 안을 볼 수 없다**(D-07). 계정은 한 사람이 하나씩 쓰고 공유하지 않는다. 사장이 직접 정비하면 사장 계정이 담당 정비사가 될 수 있다.

## 3. 데이터 범위

| 역할 | 볼 수 있는 데이터 |
|---|---|
| 사장·정비사 | 자기 정비소의 고객·차량·이력·예약·항목 **전부**(캘린더도 전체). "내 담당만" 보기는 화면 필터일 뿐 데이터 권한이 아니다. 다른 정비소 데이터는 존재 여부도 알 수 없음(404) |
| 서비스 관리자 | 정비소 목록과 운영 정보(이름·연락처·상태·생성일). 정비소별 고객 수·방문 수 같은 집계도 보지 않음 |

## 4. 거부 응답

| 상황 | 응답 |
|---|---|
| 토큰 없음·만료 | 401 `AUTH_REQUIRED` → 화면은 로그인으로 |
| 서비스 관리자 토큰으로 정비소 API | 403 `FORBIDDEN` |
| 사장·정비사 토큰으로 서비스 관리자 API | 403 `FORBIDDEN` |
| 정비사가 사장 전용 API 또는 남이 담당한 기록·예약 수정·정정 | 403 `FORBIDDEN` |
| 정비사가 3일 제한을 넘겨 수정·정정 (P0-나머지) | 403 `EDIT_PERIOD_EXPIRED` |
| 재배정 마감 후(전날까지가 아님) 일반 재배정 (P0-나머지) | 409 `ASSIGNEE_CHANGE_CLOSED` |
| 다른 정비소 데이터 | 404 `NOT_FOUND` (권한 문제가 아니라 "없음"으로 답함) |
| 정지된 정비소 로그인 (P1) | 403 `SHOP_SUSPENDED` |
| 비활성 정비사 계정 로그인 (P1) | 403 `ACCOUNT_INACTIVE` |

## 5. 지키는 방법

| 장치 | 내용 |
|---|---|
| URL 규칙 | `SecurityConfig` 한 곳: `/api/admin/**` → ADMIN, `/api/**` → OWNER·MECHANIC, 사장 전용(P1) 경로(43~49, 50)는 OWNER로 제한. 마지막은 `anyRequest().denyAll()` |
| 서비스 안 | 역할 `if` 분기를 서비스에 흩뜨리지 않는다(CONVENTIONS 4장). 사장 전용·담당·기간 판정은 **권한 판정을 한 곳**(예: 도메인의 `…Policy`/`EditRule` 하나, CONVENTIONS 4·11장 7문항 확인)에서 한다. 소속 확인은 각 도메인의 `getOwned(shopId, id)` |
| 테스트 | `EndpointGuardTest`(등록 안 된 경로는 닫힘, 서비스 관리자는 정비소 API 불가), 08의 X1~X16, 04의 R27·R29·H3·H10·K8 |
| 화면 | 사장 전용 메뉴는 정비사에게 보이지 않게 하지만, 막는 것은 서버다 |
