## 1. 한 줄 정의

> 차곡은 소규모 정비소를 위한 예약 CRM으로, 예약 일정과 고객·차량·정비 이력을 통합 관리하고, 축적된 정비 기록을 활용해 재점검 시기가 된 고객의 재예약을 지원하는 서비스이다.

- **기본 기능**: 예약 관리 (프로젝트 지정 주제가 예약 CRM)
- **CRM의 기반**: 고객·차량·정비 이력
- **차별점**: 정비 기록으로 재점검 시기를 계산해 재예약으로 잇는 것

## 2. 문제

소규모 정비소는 정비 기록을 장부나 프로그램에 남기지만, 그 기록이 "누구에게 언제 다시 연락할지"와 "예약"으로 이어지지 않는다. 예약은 전화로 받아 따로 적고, 연락 대상은 사장의 기억에 맡긴다. 바쁠수록 더 많이 놓친다.

| 문제 | 지금 어떻게 하나 | 그래서 생기는 일 |
|---|---|---|
| 예약·고객·이력이 따로 있다 | 예약은 달력·수첩, 이력은 장부·프로그램 | 예약 전화를 받으며 그 차의 지난 정비를 바로 못 본다 |
| 재연락 기준이 사장의 기억이다 | 기억나는 단골에게 연락 | 점검 시기가 된 단골을 놓쳐 재방문 기회를 잃는다 |
| 안내가 부품이 아니라 날짜 기준이다 | 마지막 정비 후 30·60·90일 일괄 문자 | 항목마다 다른 주기가 반영되지 않는다 |
| 방문 중 추가 점검을 놓친다 | 정비사가 그때그때 판단 | 같이 봐야 할 항목을 권하지 못하고 지나친다 |

### 누가 손해를 보나

- **정비소**: 점검 시기가 된 단골을 놓쳐 재방문과 추가 정비 기회를 잃는다. 한번 다른 곳에 간 고객은 다시 돌아오기 어렵다.
- **차량 소유주**: 브레이크패드·타이어처럼 안전과 직결된 항목의 점검 시기를 모른 채 지나친다. 문제가 커진 뒤 오면 비용도 커진다.

### 조사로 확인한 근거 (2026.11.19 확인)

- **기록과 연락이 분리되어 있다**: 정비소 문자 발송 가이드들은 고객 정보와 최근 정비 이력을 엑셀로 정리해 단체문자 서비스에 올리는 방식을 안내한다.
- **재방문 안내가 부품이 아니라 날짜 기준이다**: 마지막 정비 후 30·60·90일처럼 일괄 일수로 나눠 보내는 방식이 흔히 권장된다.
- **고객 입력 방식은 번거롭다**: 차주용 앱 마이클의 리뷰에서는 주행거리 자동 연동이 장점으로, 주행거리 업데이트 오류가 불만으로 꼽힌다.
- **해외에서는 상용화되어 있다**: Tekmetric·AutoVitals는 정비 주기 알림과 후속 안내를 실제 기능으로 제공한다. 실현 가능성의 근거이며, 국내 수요 규모를 증명하지는 않는다.

## 3. 대상

| 구분 | 내용 |
|---|---|
| 핵심 고객 | 소규모 독립 정비소, 개인 카센터, 경정비·소모품 교환 중심 |
| 규모 | 사장 포함 1~5인 (시장 통계가 아닌 타깃 설정) |
| 운영 특징 | 상담·마케팅 전담 직원 없이 사장이 예약·연락·정비를 함께 맡음. 전화 예약과 동네 단골 위주 |
| 우선 제외 | 대형 공식 서비스센터, 사고 수리 전문업체, 대규모 법인 차량 관리 |

### 대표 사용자 (가정)

50대 박 사장은 정비사 1명과 2인 카센터를 운영한다. 고객 대부분은 전화로 예약하거나 지나가다 들르는 동네 단골이다. 정비 내역은 장부에 꼼꼼히 남기지만, 누구에게 언제 연락할지는 기억에 의존한다. 바쁜 주에는 점검 시기가 된 단골에게 연락하지 못하고, 몇 달 뒤 그 고객이 다른 곳에서 오일을 갈았다는 이야기를 듣는다.

박 사장에게 필요한 것은 새 업무 프로그램이 아니라, 아침에 오늘 예약과 "오늘 연락할 고객"을 보여주고, 예약을 누르면 그 차의 지난 정비와 점검 시기가 바로 보이고, 차가 들어왔을 때 "같이 봐야 할 항목"을 알려주는 화면이다. 문자는 지금처럼 자기 폰으로 보낸다. 이 인물은 조사 결과를 바탕으로 한 가정이며, 정비소 인터뷰로 검증한다.

### 사용자와 관계자

| 사용자 | 하는 일 |
|---|---|
| 정비소 사장 | 예약 관리, 재점검 대상 확인, 고객 연락과 재방문 관리, 정비사 계정 추가 |
| 정비사 | 신규 고객·차량 등록, 방문 접수, 주행거리·정비 기록 입력, 추가 점검 항목 확인 |
| 서비스 관리자 | 정비소 개설·정지·재개만. 정비소 안의 데이터는 볼 수 없음 |
| 차량 소유주 | 간접 수혜자. 계정·앱 없이 사장이 보내는 안내를 받음 |

## 4. 가설

| 구분 | 가설 | 확인 방법 |
|---|---|---|
| 핵심 (P0) | 방문 기록만으로 다시 연락할 고객을 골라낼 수 있다 | 시나리오 A: 시드 이력으로 재점검 대상 목록이 기대 상태표와 같게 나오고, 목록에서 재예약까지 이어진다 |
| 핵심 (P0) | 예약에서 고객·차량·이력을 한 화면에서 보면 상담·접수가 빨라진다 | 예약 상세 패널에서 페이지 이동 없이 예약 목적·이력·점검 주기 요약을 확인 |
| 핵심 (P0) | 방문 중에 주행거리만 넣어도 같이 봐야 할 항목을 알려줄 수 있다 | 시나리오 B: 저장 전 미리보기에서 km 기준 도래 항목이 표시된다 |
| 정확도·편의 (P1) | 주행거리 추세와 연락 준비(문자 초안·결과 기록)를 더하면 놓치는 고객이 줄고 손이 덜 간다 | 월평균 추정 반영, 문자 초안 복사, 연락함 표시 |
| 확장 (P2) | 연락 이유를 넓히고(거절 후속·장기 미방문) 효과를 숫자로 보면 재방문이 늘어난다 | MVP 이후 검토 |

**개발 가설**: 전화·현장 방문 고객의 등록, 예약, 이력 조회, 점검 안내, 재예약을 한 흐름으로 연결하면 소규모 정비소의 후속 관리 업무를 줄일 수 있다.

## 5. 판단 원칙

"정비사에게 필요한 모든 기능인가?"보다 **"예약과 고객 관계 관리의 업무 흐름을 개선하는가?"**를 먼저 묻는다.

> 기능은 좁게, 정책은 깊게, 데이터 구조는 유연하게, 코드의 책임은 명확하게, 검증은 철저하게.

| 점검 결과(양호/주의) 기록 | 다음 방문 때 이어서 볼 정보가 필요 | P0-나머지 | 6개 항목 안에서만, 주기 상태와 분리 |
| 부위별 상세 점검표·차량 도면 입력 | 정비사의 전문적인 점검 지원 | P2 | 예약 CRM보다 정비 관리 시스템으로 넓어짐 |
| 읽기 전용 차량 약식 도면 | 6개 항목 상태를 한눈에 | P1 | 입력 없이 기존 계산 결과만 색으로 표시 |

| 사장 아침 알림 | 매일 아침 확인 습관 | P1 (탭 열린 상태), 웹 푸시는 P2 | 서비스 워커·스케줄러 부담 |
| 서비스가 고객에게 직접 문자·카카오톡 발송 | 연락 자동화 | Non-goal | 정비소와 고객의 직접 관계를 돕는 것이 방향. 발송 비용·책임을 지지 않음 |
| 고객용 앱·가입 | 고객이 직접 이력 확인 | Non-goal | "고객 입력 없음"이 차별점 |
| 결제·정산, 부품 재고 | 종합 업무 관리 | Non-goal | 종합 업무 프로그램과 경쟁하지 않음 |

| 마케팅 캠페인·세그먼트 | 홍보 | Non-goal | 재방문 안내가 축 |

## 7. 유사 서비스와 차별점

| 서비스 | 주요 사용자 | 강점 | 차곡의 접근 |
|---|---|---|---|
| 마이클 (국내) | 차량 소유주 | 차량 관리, 정비 기록, 교체 시기 알림, 정비소 비교·예약·결제 | 고객의 앱 사용을 전제하지 않고 정비소가 기록을 관리 |
| 마이클 파트너스 (국내) | 입점 정비소 | 예약·운영시간·정산·재고·리뷰 관리 | 플랫폼 입점에 의존하지 않는 전화·현장 고객 관리 |
| 정비마법사 (국내) | 정비업체 | 고객·이력·부품·재고·비용 관리, 교환주기 문자, 달력형 예약 | 종합 업무 프로그램과 경쟁하지 않고 예약 CRM에 집중 |
| AutoVitals (해외) | 정비소 | 정비 권장 항목, 예정일 기반 연락, 예약 연결 | 내부 대상 목록과 현장 안내 중심 |
| Tekmetric (해외) | 정비소 | 거절 정비 후속, 반복 정비 알림, 장기 미방문 연락 자동화 | 국내 소규모 정비소에 맞춘 간결한 화면과 흐름 |

차별화 방향: 고객 입력 없음 · 불완전한 이력에서도 시작 · 방문 중 안내 · 정비소별 데이터 격리 · 연락은 정비소가 직접.

## 8. 알고 있는 한계와 검증할 것

- 고객이 다른 정비소를 함께 이용하면 이력에 빈틈이 생긴다. 외부 정비·거절 기록과 "미확인" 상태로 보완한다.
- 점검 주기 상태는 점검 시기 안내이지 부품 상태 진단이 아니다. 점검 결과(양호/주의)도 정비사의 관찰 기록일 뿐이다.
- 유사 서비스 조사는 공개 자료 기반이다. 실제 정비소 인터뷰는 하지 않았다.
- 검증이 필요한 것: 실제 정비소의 예약·고객 관리 방식, 방문 1건당 입력 시간, 새 도구 도입 의사, 사장이 문자 초안을 실제로 쓸지.
