## 1. 제품 정의

> 차곡은 소규모 정비소를 위한 예약 CRM으로, 예약 일정과 고객·차량·정비 이력을 통합 관리하고, 축적된 정비 기록을 활용해 재점검 시기가 된 고객의 재예약을 지원하는 서비스이다. (D-31)

- **기본 기능**: 예약 관리
- **CRM의 기반**: 고객·차량·정비 이력
- **차별점**: 재점검 시기 기반 재예약 (주기 계산 · 재점검 대상 · 방문 중 안내)
- **판단 원칙**: "예약과 고객 관계 관리의 업무 흐름을 개선하는가?"를 먼저 묻는다.
- **대상**: 상담 직원 없이 사장이 예약·연락까지 맡는 1~5인 독립 정비소의 사장과 정비사. 서비스 관리자는 정비소를 열고 닫기만 한다. 차량 소유주는 계정 없는 간접 수혜자.

## 2. 단계 정의

| 단계 | 기준 | 이번 프로젝트에서 |
|---|---|---|
| P0-핵심 | 재방문 순환의 최소 경로. 시나리오 A·B가 끝까지 돈다 | 가장 먼저. M2 통합 검증에서 시연 |
| P0-나머지 | 시나리오 A·B를 P1 없이 완결시키고 기본 운영을 갖춤 | M2 통합 검증 통과 후 |
| P1 | 같은 가설의 정확도와 운영 편의 | P0-나머지 다음. M3 MVP 검증에서 확인 |
| P2 | 새 가설, 새 사용자 접점, 외부 연동 | M3 MVP 검증 통과 후 `결정` 이슈로 A 묶음부터 하나씩 (D-29). 그전에는 문서로만 |
| Non-goal | 차곡의 방향과 맞지 않음 | 만들지 않고 확장 방향으로도 소개하지 않음 |

**MVP = P0 + P1** (D-28). 차례가 오지 않은 단계의 기능과 Non-goal은 빈 화면·연결 안 된 버튼·쓰지 않는 API·테이블로 미리 만들지 않는다. 예외: 정비 구분값 4개(교체·점검·외부·거절)처럼 "값은 처음부터"로 정한 것(D-06). 예약 상태 "노쇼"와 점검 결과 칸은 P0-나머지에서 마이그레이션으로 추가한다.

## 5. 안 만들 것 — Non-goal

| 항목 | 이유 |
|---|---|
| 서비스가 고객에게 직접 문자·카카오톡·이메일 발송 | 정비소와 고객의 직접 관계를 돕는 것이 방향. 발송 비용·책임을 지지 않음 |
| 결제·정산, 부품 재고 | 종합 업무 프로그램과 경쟁하지 않음 |
| 고객용 앱·가입 | "고객 입력 없음"이 차별점 |
| 정비소 간 공동 이력 | 목표는 "우리 정비소의 고객 관계" |
| 마케팅 캠페인·세그먼트 빌더 | 재방문 안내가 축 |

## 6. 범위를 지키는 규칙

- 범위를 줄여야 하면 `결정` 이슈로 정하고, P0-핵심과 정비소 격리는 유지한다. 기능은 통째로 빼고 00·04·08에 "보류"로 표시한다.
- 개발 시작 후 범위 추가는 `결정` 이슈 + 전원 합의가 먼저다(`chagok-scope-guard`로 판정).
- M4 기능 동결 이후 새 기능을 넣지 않는다. 완료 정의를 채우지 못한 기능은 시연에서 뺀다.

## 7. 완료의 정의 (기능 하나)

화면에서 동작하는 것만으로 완료가 아니다. 아래를 모두 충족해야 완료로 센다. 하나라도 빠지면 미완료이며 M4 기능 동결 이후 시연에 넣지 않는다.

1. **요구사항·정책**: 03 요구사항과 04 기능 규칙·05 정책을 지킨다
2. **API 계약**: 요청·응답·에러 코드가 08(표·JSON 예시)과 같다. 공통 응답·공통 오류 처리(05 POL-120~129)를 따른다
3. **정상·오류·경계**: 정상 흐름과 입력 오류·경계값·상태 전이 오류가 의도대로 동작한다
4. **권한·격리**: 역할별 권한(06)과 정비소 격리(08 X-xx)를 지킨다
5. **테스트**: 관련 테스트(04의 T-xx·R-xx, 08의 X-xx, ArchitectureTest)를 함께 작성했고 CI에서 통과했다. 실행하지 못한 테스트는 이유와 함께 "미검증"으로 남긴다
6. **회귀**: 기존 기능에 영향이 없음을 확인했다(CI 전체 통과 + 관련 화면 확인)
7. **연결 실행**: 백엔드·프론트가 각 레포 `develop`에 들어가고, 두 레포를 함께 띄워 다른 팀원이 빈 DB에서 확인했다. 시연에 쓸 시드가 있다(07 7장)
8. **문서**: 바뀐 명세가 `chagok-docs`에 반영됐다
9. **담당자 확인**: 담당 개발자가 위 항목을 직접 확인했다. AI가 "완료"라고 보고해도 실제 빌드·테스트 결과가 없으면 완료가 아니다(D-48)

## 9. 시연 시나리오

- **시나리오 A (재점검 → 재예약)**: 홈 "오늘 연락할 고객 N명" → 재점검 대상 목록 → 전화 → 목록에서 예약 등록 → 대상 목록에 "예약 있음" → 예약일에 방문 완료 → 정비 기록 → 그 항목이 목록에서 빠짐.
- **시나리오 B (방문 중 안내)**: 예약 상세 패널 또는 차량 검색 → 방문 접수 → 주행거리 입력 → 미리보기에서 km 기준 "도래" 항목 확인 → 권유 → 교체(주기 재시작) 또는 거절(주기 유지, P0-나머지부터 "지난 방문 거절" 표시).
- **격리**: A 정비소 계정으로 B 정비소 고객 조회 → 없음(404). 서비스 관리자 계정으로 고객 목록 → 권한 없음(403).
