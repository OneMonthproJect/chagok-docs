# 기준 문서 — 문서끼리 어긋날 때

> 원본: `chagok-docs/.claude/rules/source-of-truth.md`. 코드 레포의 사본은 고치지 않는다.

문서와 코드가 다를 때는 `ai-rules.md`「AI만의 규칙」대로 문서가 기준이다. 이 파일은 **문서끼리** 다를 때 무엇을 따를지 정한다. 문서는 모두 `chagok-docs`에 있다.

## 판단 순서 (위가 우선)

1. **결정 기록** — `docs/13_changelog_기획변경이력.md`와 닫힌 `결정` 이슈(`chagok-docs`)의 「결정 결과」. 날짜가 늦은 것이 우선이다.
2. **기준 문서** — 00 · 04 · 07 · 08. 문서마다 자기 영역의 원본이다.

   | 영역 | 원본 |
   |---|---|
   | 범위 · 단계 (P0-핵심 / P0-나머지 / P1 / P2 / Non-goal), MVP = P0 + P1 | 00 PRD |
   | 기능 ID · 기능 규칙 · 주기 규칙 · T-xx | 04 기능명세서 |
   | 테이블 · 컬럼 · 제약 · 격리 I-xx · 시드표 | 07 ERD |
   | API 번호 · 요청 · 응답 · 에러 코드 · X-xx · JSON 예시 | 08 API |

3. **나머지 문서** — 01 · 02 · 03 · 05 · 06 · 09 · 10 · 11 · 12 · `etc/`. 위 1 · 2에 맞춰 고치는 대상이다.

## 어긋났을 때

- **결정 기록과 문서 본문이 다르면** 결정 기록이 맞다. 본문은 반영이 빠진 것으로 보고, 위치와 해당 changelog 줄을 함께 보고한다.
- **나머지 문서가 기준 문서와 다르면** 기준 문서가 맞다. 그 영역의 원본 문서와 위치를 근거로 단다.
- **기준 문서끼리 다르면** 어느 쪽도 고르지 않는다. 예: 08 응답 필드가 07에 없는 컬럼을 가리킴, 04 기능 ID가 00 범위표에 없음. 양쪽 원문과 위치를 ❓로 보고하고 `결정` 이슈를 제안한다.
  - 단, 00에서 P2(MVP 점검 전) · Non-goal인 기능이 다른 문서에 구현 대상으로 들어와 있으면 00이 맞다(범위는 00의 영역이다).
- 기준 문서로 답이 정해지지 않는 것은 고치지 않는다. 보고하고 사람에게 결정을 넘긴다.

## 고칠 때

- 관문 1 이후 07 · 08을 바꾸는 절차는 `CONTRIBUTING.md` 7장을 따른다(`결정` 이슈 → `chagok-docs` 문서 PR + 13 changelog → 코드 레포 PR에 문서 PR 링크).
- 영향 범위 찾기와 문서 · 코드 대조는 `chagok-spec-sync` 스킬을 쓴다.
