# 차곡 시드 데이터

> 경로 표기: `docs/…`·`CONVENTIONS.md`·`CONTRIBUTING.md`는 `chagok-docs` 기준(코드 레포에서는 `../chagok-docs/…`), `chagok-backend/…`·`chagok-frontend/…`는 각 레포 루트 기준이다(`.claude/rules/ai-rules.md`「작업 폴더와 경로」). 필요한 레포가 작업 폴더에 없으면 지어내지 말고 읽지 못한 것으로 보고한다.

시드는 시연의 무대다. 기능이 다 있어도 시드가 어긋나면 대상 목록이 비고, 발표 날 날짜가 바뀌면 "도래"가 "미확인"으로 무너진다. 이 스킬은 **07 시드표를 원본으로** 시드 파일을 만든다. 시드 파일은 `chagok-backend/db/seed/demo_seed.sql`이다(classpath 밖 — 서버·Flyway가 읽지 않는다, D-43). 시연 전용 DB(💡 `chagok_demo`)에만 `db/seed/run-demo-seed.sh`로 넣는다. 규칙의 원본은 `db/seed/README.md`와 07 7장이다.

## 1. 읽을 것

| 문서·코드 | 가져오는 것 |
|---|---|
| `docs/07_*` 시드 구성 | 정비소·계정·고객·차량·정비 항목·기록 건수와 의도 (원본) |
| `chagok-backend/src/main/resources/db/migration/V*.sql` (번호 순서대로 모두) | 테이블·컬럼·제약·CHECK 값. **마이그레이션은 고치지 않는다** |
| `docs/04_*` 주기 규칙, T-xx | 교체·외부만 주기 초기화, 임박 = 기준일 + 1개월 이내, 도래 경계 ≥, km 판정 |
| 07 시드표의 주기표 (현재 시드 파일의 `service_item`) | 정비 항목 6개의 개월·km 주기값 |
| `docs/08_*` X-xx, JSON 예시 | 격리 테스트에 필요한 다른 정비소 데이터. 08 JSON 예시 값은 시드에서 가져오므로(CONTRIBUTING 7장) 예시와 시드 값이 같은지 |
| `docs/13_*`, 닫힌 `결정` 이슈 | 주기값·시드 구성이 바뀐 결정 (07 본문보다 우선) |
| `CONTRIBUTING.md` 6장·9장 | 빈 DB 시나리오 A·B·격리 확인 순서, 매일 마감 전 "대상 목록 = 기대 상태표" 확인 |

07에 없는 것을 시드에 넣어야 하면 멈추고 DB관리에게 `chagok-docs`에서 07부터 고치자고 알린다(pr-check가 시드 변경 시 07 확인을 경고한다). 13의 결정이 07 본문에 아직 반영되지 않았으면 결정을 따르되 07 수정이 필요하다고 보고한다(`.claude/rules/source-of-truth.md`). 07과 04가 서로 다르면 시드를 만들지 말고 ❓로 보고한다.

## 2. 날짜 규칙 — 오늘 기준 상대값

시드는 서버가 넣지 않는다. 시연 전날 DB 담당자가 시연 DB를 새로 만들고 → 서버를 그 DB로 띄워 Flyway를 적용하고 → `run-demo-seed.sh`로 시드를 넣는다. 그날 기준으로 다시 들어가므로 상대 날짜로 쓰면 시연 날 언제든 같은 화면이 나온다.

- 시드 파일에 `DELETE`·`TRUNCATE`·`DROP`·`ALTER`·`CREATE`·`UPDATE`를 쓰지 않는다(실행기가 거부한다). 다시 넣을 때는 시연 DB를 새로 만든다. 실행기는 DB 이름이 `_demo`로 끝나는지, Flyway가 적용됐는지, `shop`이 비어 있는지 확인한다.
- 시연 계정(사장·정비사·관리자)의 비밀번호는 `1234`이고 **BCrypt 해시**로 넣는다. `password_change_required = false`. 평문 비밀번호를 SQL에 쓰지 않는다(D-44).
- 마이그레이션 파일(`V*`)에 시드를 넣지 않는다. 운영 DB에도 들어가 버린다.

```sql
-- 좋음: 6개월 주기 항목을 6개월 전에 교체 → 오늘 "도래"
DATE_SUB(CURDATE(), INTERVAL 6 MONTH)
-- 나쁨: 날짜가 지나면 상태가 바뀌어 시연이 무너짐
'2026-06-01'
```

- 경계 바로 위·아래(정확히 1개월, 정확히 주기 날짜)는 **T-xx 경계를 일부러 보여 줄 데이터에만** 쓴다. 나머지는 경계에서 최소 1주 떨어뜨린다. DB 시간대와 앱 `Clock` 시간대가 다르면 자정 근처에 하루가 밀리기 때문이다.
- 월말(31일)·윤년 날짜는 시드에 쓰지 않는다. 그 검증은 cycle 단위 테스트가 한다.

## 3. 반드시 들어갈 묶음

| 묶음 | 목적 | 최소 구성 |
|---|---|---|
| 정비소 2곳 (A·B) | 격리 시연 X-xx (08 표기 그대로) | B 정비소에도 고객·차량 1~2건 |
| 계정 | 로그인 | A 사장 · A 정비사 · B 사장 · 플랫폼 관리자 1명씩 |
| 상태별 차량 (A 정비소) | 시나리오 A 대상 목록 | 미확인 · 여유 · 임박 · 도래(개월) · 도래(km) 각 1대 이상 |
| 점검·거절 기록 | "주기를 다시 시작하지 않음" 시연 | 마지막 기록이 점검인데 이전 교체 기준으로 도래인 차량 1대 |
| 예약 있는 대상 | 대상 목록 "예약 있음" 표시 | 도래 차량 중 1대에 오늘 이후 예약 |
| 시나리오 B용 차량 | 방문 접수 → 주행거리 입력 → km 도래 | 기준 기록 주행거리 + 주기 km에 가까운 차량 1대 (입력값 예시를 보고에 적기) |
| 이력 많은 차량 | 차량 상세 이력 화면 | 한 차량에 기록 3건 이상 |
| 지난 점검 주의 | 패널·미리보기·대상 목록의 "지난 점검 주의" 표시 (P0-나머지부터) | 마지막 기록이 "점검·주의 + 메모"인 항목이 있는 차량 1대 (가능하면 대상 목록에도 뜨는 차량) |
| 오늘 예약 | 홈 "오늘 예약 N건"·오늘 예약 목록·예약 상세 패널 | 오늘 예약 2건 이상, 그중 1건은 예약 목적 항목 선택, 1건은 기타 + 메모 |

- 비밀번호는 평문으로 넣지 않는다. 앱의 `PasswordEncoder`로 만든 해시를 넣고, 시연 계정·비밀번호는 보고에만 적는다(커밋 메시지·PR 본문에 쓰지 않는다).
- 이름·전화번호·차량번호는 가짜임이 드러나게: `010-0000-0001`, `12가0001`. 실제 사람 정보처럼 보이는 값 금지.
- 상태(미확인/여유/임박/도래)는 칼럼이 없으므로 넣지 않는다(CONVENTIONS 1장 6번). 기록 날짜·주행거리로 결과가 나오게 만든다.

## 4. 절차

1. 1장 문서를 읽고 07 시드표와 현재 시드 파일의 차이를 표로 만든다.
2. 3장 묶음별로 "기대 상태"를 먼저 정한다(어느 차량·항목이 어떤 상태로 보여야 하는지).
3. 2장 날짜 규칙으로 기록 날짜·주행거리를 역산해 시드 파일을 쓴다. INSERT 순서는 외래키 순서(shop → staff/admin → customer → vehicle → service_item → maintenance_record → reservation).
4. 가능하면 시연 DB에 실행기로 넣고 앱을 띄워 대상 목록 API를 호출해 기대 상태와 비교한다. 띄우기 전에 무엇을 할지 한 줄로 알린다. 못 돌렸으면 "실행 미확인".
5. 결과를 보고한다. DB에 직접 넣거나 커밋하지 않는다.
