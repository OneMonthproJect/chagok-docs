# 차곡 범위 지킴이

> 경로 표기: `docs/…`·`CONVENTIONS.md`·`CONTRIBUTING.md`는 `chagok-docs` 기준(코드 레포에서는 `../chagok-docs/…`), `chagok-backend/…`·`chagok-frontend/…`는 각 레포 루트 기준이다(`.claude/rules/ai-rules.md`「작업 폴더와 경로」). 필요한 레포가 작업 폴더에 없으면 지어내지 말고 읽지 못한 것으로 보고한다.

남은 일보다 범위를 크게 잡거나 합의 없이 기능을 더하면, 마지막에 줄이느라 완성도가 무너진다. 이 스킬은 **추가 요청이 들어온 그 순간**에 판정 근거를 모은다. 코드는 쓰지 않는다. 결정은 사람이 하고, 개발 시작 후 범위 추가는 `결정` 이슈 + 전원 합의가 먼저다(CONTRIBUTING 3장).

## 1. 읽을 것

| 문서 | 가져오는 것 |
|---|---|
| `docs/00_*` | 단계(P0-핵심/P0-나머지/P1/P2), MVP = P0 + P1, P2 3묶음과 우선순위, Non-goal, 결정 D-xx |
| `docs/04_*` | 이미 있는 기능 ID (같은 기능이 이미 있는지) |
| `docs/13_*`, 닫힌 `결정` 이슈 | 같은 제안이 이미 결정·거절됐는지 (본문보다 우선, `.claude/rules/source-of-truth.md`) |
| `docs/12_*`, `gh issue list --repo OneMonthproJect/chagok-backend`·`chagok-frontend` | 열린 P0·P1·P2 이슈 수, 담당별 남은 일 |
| `chagok-docs/README.md` 마일스톤 표, 마일스톤(`gh api repos/OneMonthproJect/chagok-backend/milestones`), 태그(`v0.5-m2-integration`·`v0.8-m3-mvp` 유무) | 지금 단계, 마일스톤 날짜 |
| `CONTRIBUTING.md` 3장·9장 | 범위 규칙, 지금 단계의 규칙 |
| `CONVENTIONS.md` 9장 | 이 변경이 건드리는 곳의 예상 개수 |

지금 단계와 다음 마일스톤까지 남은 일은 README 마일스톤 표·마일스톤·태그·열린 이슈로 먼저 추정하고, 그래도 모르면 사용자에게 묻는다. 추정했으면 근거에 "추정"이라고 적는다.

## 2. 질문 5개

1. **이미 범위 안인가?** 04에 같은 기능 ID가 있으면 새 기능이 아니라 기존 이슈의 일이다.
2. **어느 단계에 해당하나?** 00 기준 P0 / P1 / P2(A·B·C 묶음) / Non-goal / 없음.
3. **지금 단계에서 허용되나?** M1 설계 확정 전은 `chagok-docs` 작업 중심, P0-나머지·P1은 M2 통합 검증 통과 후(P1 이슈는 그 전에 열지 않음), **P2·Non-goal은 이번 프로젝트에서 착수하지 않는다(D-70, M3 통과 후에도 같다)**, 동결 후 `feature/` 금지(`FEATURE_FREEZE=true`), M5 최종 시연 직전 기능 추가 금지.
4. **하루 안에 PR 하나로 끝나나?** 아니면 쪼갤 수 있나. CONVENTIONS 9장 표보다 많은 곳을 건드리면 구조 문제 신호.
5. **빼면 시나리오 A·B 시연이 깨지나, 덜 멋질 뿐인가?** 열린 P0-핵심 이슈가 있으면 그것보다 먼저일 수 없다.

## 3. 판정 (하나만)

| 판정 | 기준 | 다음 행동 |
|---|---|---|
| **진행** | 이미 04·00 범위 안, 지금 단계에서 허용, 하루 안 | `chagok-issue-writer`로 이슈 작성 |
| **쪼개기** | 범위 안인데 하루를 넘음 | 하루 단위 이슈 2~3개 제목 제안 |
| **결정 이슈** | 00에 없는 새 기능·범위 확장, 또는 단계 규칙과 충돌 | 아래 초안. 합의 전 브랜치 금지 |
| **보류** | 차례가 오지 않은 단계(M2 통합 검증 전 P1), 또는 시연이 안 깨지는 추가 | 새로 만들지 않고 보류. P2 후보는 00 4장 참고 자료에 있으면 그대로 |
| **거절** | P2·Non-goal(D-70), 동결 후 기능, M5 최종 시연 직전 | 근거 절을 적고 멈춤 |

애매하면 보류 쪽으로 판정한다. 열린 P0-핵심 이슈가 있는데 새 기능을 진행으로 판정하지 않는다. P2 착수 의견은 D-70에 따라 M3 통과 후에도 "거절"로 판정하고 00 4장 참고 자료로 남기자고만 안내한다. 판단 기준은 D-70의 3가지(없으면 구현 불가 / 필수 보안·법적 요구 / 기존 범위 안 최소 변경)다.

## 4. 출력

```markdown
## 판정: 보류
한 줄 이유 (근거: 00 §…, CONTRIBUTING 9장 …)

## 근거
- 범위: P1 / 00 §…
- 지금 단계: M3 MVP 검증 전 (추정: `v0.8-m3-mvp` 태그 없음)
- 열린 P0·P1 이슈: 3건 (backend#…, frontend#…)
- 예상 건드리는 곳: (CONVENTIONS 9장 비교)
- 빼면: 시연 영향 없음 / 시나리오 A의 … 단계가 끊김

## 대신 할 수 있는 것
- …
```

판정이 **결정 이슈**면 `chagok-docs`의 `.github/ISSUE_TEMPLATE/decision.md` 양식으로 초안을 붙인다. 특히 「이 결정이 깨지는 상황」과 「영향받는 곳」(00·04·07·08·13, 코드 레포)을 채우고, 올리는 것은 사람이 한다(`gh issue create --repo OneMonthproJect/chagok-docs`).

## 5. 범위를 줄이는 요청일 때

"이 기능 빼자"도 같은 질문으로 본다. 다만 판정은 **통째로 빼기 / 유지** 둘 중 하나다. 기능의 일부만 남기면 문서에 유령 API·화면이 생기기 때문이다(CONTRIBUTING 3장).

- 빼기로 판정하면: 같은 날 `chagok-docs`에서 00·04·08에 "보류" 표시를 넣는 것까지 다음 행동으로 적고, 영향 범위는 `chagok-spec-sync` 모드 A로 넘긴다.
- 빼면 시나리오 A·B가 끊기면: 빼지 말고 다른 P0-나머지를 먼저 줄이자고 제안한다.
- P1을 빼는 것은 MVP를 줄이는 일이다. 판정은 항상 **결정 이슈**이다.

```markdown
## AI 사용 기록 (형식·제출 위치는 `ai-rules.md` 「AI만의 규칙」)
| 날짜 | - | chagok-scope-guard | 범위 판정: 무엇 → 판정 | 사람이 바꾼 것: (사람이 채움) |
```
